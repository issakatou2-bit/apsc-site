第1章 プロセスとスレッド

プロセスとスレッド（シラバスの用語例から）
タスク（プロセス）

スレッド
1つのプロセスの中で動く、さらに小さな処理の流れ。軽量プロセスとも
多重プログラミング

ここではタスクをプロセスとして説明するわ。OSがCPUやメモリを割り当てる仕事の単位よ。

スレッドは、1つのプロセスの中で動く、もっと小さな処理の流れ。軽量プロセスとも呼ぶわ。

第2章 タスクの3つの状態

タスクの3つの状態（シラバスの用語例から）
実行状態
いまCPUを使っている状態。ここでは一度に一つのタスクを実行する場合を想定
実行可能状態
いつでも動けるが、CPU の順番を待っている
待ち状態
入出力の終わりなど、何かが起きるのを待っている
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 5 ソフトウェア 1.(4)（用語例）
めたん
第2章は、タスクの状態。ここでは生成・終了を除き、3つの状態に分けて考えるわ。
めたん
実行状態は、CPUを使っている状態。ここでは、一度に一つのタスクを実行する場合を考えるわ。
めたん
実行可能状態は、いつでも動けるけれど、CPUの順番を待っているタスク。
めたん
待ち状態は、入出力が終わるのを待つなど、何かが起きるのを待っているタスクよ。
ずんだもん
実行可能状態と待ち状態は、どっちも待っているのだ。同じなのだ？
めたん
そこがちがうの。実行可能はCPUさえ来ればすぐ動ける。待ちは、CPUをもらっても、まだ動けないの。
めたん
たとえば、ファイルの読み込みを待っているタスクに CPU を渡しても、データが来るまで何もできないわ。
ずんだもん
データ待ちでは動けないのだ。

第3章 状態の移り変わり

状態の移り変わり
  1. 実行可能 → 実行：順番が来て CPU を渡される（ディスパッチ）
  2. 実行 → 待ち：入出力などの完了を待つ必要が生じる
  3. 待ち → 実行可能：入出力が終わって、また動けるようになる
  4. 実行 → 実行可能：プリエンプティブ方式では、時間切れなどで実行を中断する
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 5 ソフトウェア 1.(4)（用語例）
めたん
第3章は、状態の移り変わり。まず、実行可能から実行へ。
めたん
順番が来たタスクにCPUを渡すことを、ディスパッチと呼ぶわ。渡す役目がディスパッチャね。
めたん
実行中のタスクが、入出力の完了を待つ必要があると、待ち状態へ移るの。
めたん
その間は、実行可能なほかのタスクにCPUを割り当てられるわ。
めたん
入出力終了割込みなどで完了が知らされると、待ちから実行可能に戻るわ。
ずんだもん
待ちが終わったら、すぐ実行になるのだ！
めたん
そこがちがうの。待ちから直接、実行にはならないの。いったん実行可能の列に並び直すのよ。
めたん
そのときCPUは、ほかのタスクが使っているかもしれないでしょう。だから順番を待つのよ。
ずんだもん
えっ、待ったあとも順番待ちなのだ。
めたん
プリエンプティブ方式では、時間切れなどをきっかけに、実行から実行可能へ戻すことがあるわ。
めたん
OSがCPUを取り上げられるのがプリエンプティブ方式。タスクが自分で手放すまで待つのが、ノンプリエンプティブ方式よ。
ずんだもん
逆に、実行可能から待ちに行くことは、あるのだ？
めたん
この3状態のモデルでは、実行可能から待ちには移らないわ。実行中に入出力などの完了を待つの。

第4章 スケジューリングの方式

スケジューリングの方式（シラバスの用語例から）
到着順（FCFS）
来た順に CPU を渡す
ラウンドロビン
決めた時間ずつ、順番に CPU を渡す
優先順
優先度の高いタスクから。待つほど優先度を上げる動的な方式も
処理時間順（SJF）
処理時間の短いタスクから

めたん
第4章は、スケジューリングの方式。実行可能のタスクのうち、だれにCPUを渡すかの決め方よ。
めたん
到着順、FCFSは、来た順にCPUを渡すもの。
めたん
ラウンドロビンは、決めた時間ずつ、順番にCPUを渡すもの。
めたん
優先順は、優先度の高いタスクから。待った時間に応じて優先度を上げていく、動的なやり方もあるわ。
めたん
優先度を最初に決めて変えないのが静的、途中で変えるのが動的な優先順位方式よ。
ずんだもん
優先度を変える方式もあるのだ。
めたん
処理時間順、SJFは、処理時間の短いタスクから先に動かすの。
ずんだもん
短いものから片付けると、待ち時間の合計が減りそうなのだ。
めたん
短いタスクが次々に来ると、長いタスクはいつまでも順番が来ないことがあるの。
到着順とラウンドロビンの対決
到着順（FCFS）ラウンドロビン
やり方来た順に割当て到着順にCPUを割り当て、終了または待ち状態になるまで実行する少しずつ交代タイムクウォンタムを使い切ると、未完了のタスクを実行可能待ち行列の最後へ
特徴しくみが簡単長いタスクの後ろでは、短いタスクも長く待つみんなに順番実行可能待ち行列のタスクに、順番にCPUを割り当てる
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 5 ソフトウェア 1.(4)（用語例）
めたん
ここで、到着順とラウンドロビンを対決させるわ。
めたん
到着順は、来た順にCPUを割り当て、終了するか、入出力などで待ち状態になるまで実行するの。
めたん
ラウンドロビンは、タイムクウォンタムを使い切ると、未完了のタスクを実行可能待ち行列の最後へ回すの。
めたん
到着順はしくみが簡単。でも長いタスクの後ろだと、短いタスクも長く待たされるわ。
めたん
ラウンドロビンは、実行可能待ち行列のタスクに、順番にCPUを割り当てるの。
めたん
ただ、タイムクウォンタムを短くしすぎると、切り替えの手間が増えてしまうの。
めたん
タイムクウォンタムの長さは、反応の速さと、むだのバランスで決めるのよ。

第5章 排他制御と待ちすぎ

排他制御と待ちすぎ
  1. 排他制御：共有データなどへの競合するアクセスを、一度に一つに制限する
  2. デッドロック：たがいに相手の鍵が空くのを待って、どちらも進めない
  3. リソーススタベーション：必要な資源を割り当てられず、待ち続ける
出典：IPA シラバス Ver.7.2 p.23〜24、令和6年度 秋期 午前 問16、OSTEP「Concurrency: An Introduction」「Common Concurrency Problems」。排他制御・デッドロックは一般的な説明
めたん
第5章は、排他制御と、待ちすぎの話。
めたん
2つのタスクが同じデータを同時に書き換えると、片方の結果が消えてしまうことがあるの。
めたん
鍵を使って共有データへの同時アクセスを制限するのは、排他制御の一例よ。
めたん
でも、2つのタスクが、たがいに相手の鍵が空くのを待つと、どちらも進めなくなる。これがデッドロック。
めたん
複数の鍵を取る順番を統一するのは、デッドロックを防ぐ工夫の一つよ。
めたん
リソーススタベーションは、必要な資源を割り当てられず待ち続けること。SJFでも起こり得るわ。
めたん
待った時間に応じて優先度を上げる方式は、これを防ぐための工夫よ。

過去問に挑戦

ノンプリエンプティブ方式のタスクの状態遷移に関する記述として，適切なものはどれか。
  • ア　OS は実行中のタスクの優先度を他のタスクよりも上げることによって，実行中のタスクが終了するまでタスクが切り替えられるのを防ぐ。
  • イ　実行中のタスクが自らの中断を OS に要求することによってだけ，OS は実行中のタスクを中断し，動作可能な他のタスクを実行中に切り替えることができる。
  • ウ　実行中のタスクが無限ループに陥っていることを OS が検知した場合，OS は実行中のタスクを終了させ，動作可能な他のタスクを実行中に切り替える。
  • エ　実行中のタスクより優先度が高い動作可能なタスクが実行待ち行列に追加された場合，OS は実行中のタスクを中断し，優先度が高い動作可能なタスクを実行中に切り替える。
答えを見るイ　実行中のタスクが自らの中断を OS に要求することによってだけ，OS は実行中のタスクを中断し，動作可能な他のタスクを実行中に切り替えることができる。
出典：令和6年度 春期 応用情報技術者試験 午前 問16

過去問に挑戦。1問目は、令和6年度春期の午前、問16よ。
めたん
ノンプリエンプティブ方式のタスクの状態遷移として、適切なものはどれか。5秒で考えてみて。
めたん
答えはイ。実行中のタスクが自ら中断を要求したときだけ、OSは中断して他のタスクに切り替えるの。
めたん
エの、優先度の高いタスクが来たら中断して切り替える、はプリエンプティブ方式の動きね。
めたん
アの優先度の引上げは、ノンプリエンプティブ方式の説明ではないわ。
めたん
ウの無限ループの検知と強制終了も、この方式の説明ではないわ。
タスクスケジューリング方式の説明のうち，特定のタスクが CPU 資源の割当てを待ち続ける可能性が最も高いものはどれか。
  • ア　各タスクの優先度を決めて，優先度が高い順に実行し，CPU 割当てまでの待ち時間の長さに応じて優先度を徐々に上げていく。
  • イ　各タスクを実行可能待ち行列に置かれた順に実行し，一定時間が経過したら実行を中断して実行可能待ち行列の最後尾に加える。
  • ウ　処理予定時間が最も短いタスクから順に処理を実行する。現在実行中の処理が終了するか，又は何らかの要因によって中断されたとき，次のタスクを開始する。
  • エ　タスクがシステムに到着した順に実行可能待ち行列の最後尾に加え，常に実行可能待ち行列の先頭のタスクに CPU を割り当てる。
答えを見るウ　処理予定時間が最も短いタスクから順に処理を実行する。現在実行中の処理が終了するか，又は何らかの要因によって中断されたとき，次のタスクを開始する。
出典：令和6年度 秋期 応用情報技術者試験 午前 問16

まとめ

ここだけ覚える
  1. タスクの状態は、実行・実行可能・待ちの3つ
  2. 待ちから直接、実行にはならない。いったん実行可能へ
  3. ラウンドロビンは時間切れで交代。到着順は終了または待ち状態になるまで実行
  4. 処理時間順（SJF）は、長いタスクが待たされ続けることがある
  5. 排他制御は、共有データなどへの競合するアクセスを一度に一つに制限する
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.23〜24、令和6年度 春期・秋期 午前 問16。本文の要点を要約
めたん
まとめよ。タスクの状態は、実行、実行可能、待ちの3つ。
