めたん
第3章は、縦と横のパリティ。パリティを組み合わせると、直すこともできるの。
めたん

めたん

第4章 チェックサムとCRC

チェックサム（説明のための単純な例）
送る側
25・40・60 を足して 125 を付ける
受け取る側
もう一度足して、付いてきた値と比べる
弱いところ
順番が入れ替わっても、合計は同じ
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 1 基礎理論 4.(1)④ 誤り検出・訂正
めたん
第4章は、チェックサムとCRC。
めたん
チェックサムは、データを区切って足した値を、検査用に付けるしくみよ。
めたん
画面は単純な例。25、40、60を足して、125を付けて送るわ。
めたん
受け取った側も、もう一度足す。付いてきた値と違えば、誤りがあると分かるの。
ずんだもん
合計が合えば、中身もきっと同じなのだ！
めたん
そうとは限らないわ。この例だと、順番が60、25、40に入れ替わっても、合計は125のまま。
めたん
単純な足し算では、こういう誤りを見逃すことがあるの。
CRC（巡回冗長検査）
  1. データの後ろに必要な数の0を足し、生成多項式で割る（けたごとの排他的論理和）
  2. 送る側：その余りを、検査用のデータとして付けて送る
  3. 受け取る側：付いてきた分も含めて、同じ生成多項式で割る
  4. 余りが0なら誤りなしとみなし、0でなければ誤りあり
めたん
そこでCRC。巡回冗長検査とも言うわ。
めたん
データの後ろに必要な数の0を足し、生成多項式で割るの。
めたん
送る側は、その余りを検査用のデータとして、データの後ろに付けて送る。
めたん
受け取る側は、付いてきた分も含めて、同じ生成多項式で割るわ。
めたん
余りが0なら誤りなしとみなす。0でなければ、どこかに誤りがあるの。
例：データ 1101、生成多項式 1011（説明のための例）
後ろに 000 を足して割る
1101000 を 1011 で割ると、余りは 001
余りを付けて送る
1101001
受け取って同じ数で割る
1101001 を 1011 で割ると、余りは 0（誤りは見つからない）
めたん
例で見てみるわ。データは1101、生成多項式は1011とするわね。
めたん
割る数が4けたなので、後ろに000を足す。検査用の余りは3けたで表すわ。
めたん
この割り算は、引き算の代わりに、けたごとの排他的論理和を使う。くり上がりも、くり下がりも無いわ。
ずんだもん
くり上がりなしの計算なのだ。
1101000 を 1011 で割る（けたごとの排他的論理和）
  1. 先頭の1に合わせて 1011 → 0110000
  2. 次の1に合わせて 1011 → 0011100
  3. 次の1に合わせて 1011 → 0001010
  4. 次の1に合わせて 1011 → 0000001：余りは 001
めたん
割り算を追ってみるわ。先頭の1に1011を合わせて、けたごとに排他的論理和を取る。
めたん
同じなら0、違えば1。結果は0110000ね。
めたん
次の1に合わせて、もう一度。0011100。
めたん
さらに次の1に合わせて、0001010。
めたん
最後にもう一度で、0000001。残った下の3けた、001が余りよ。
ずんだもん
引き算なのに、くり下がりを気にしなくていいのは楽なのだ。
めたん
1101の後ろに余り001を付けて、1101001を送るわ。
めたん
受け取った側が1101001を1011で割ると、余りは0。誤りは見つからないわ。
ずんだもん
分かったのだ。受け取った側は、付いてきた検査用のデータで割るのだ！
めたん
はずれよ。割るのは、送る側と同じ生成多項式。検査用のデータで割るのではないわ。
チェックサムと CRC の対決
チェックサムCRC
計算足し算区切ったデータを足した値割り算の余り生成多項式で割った余り
特徴しくみが簡単入れ替わりなどを見逃すことがあるまとまった誤りの検出に強い検出できる範囲は生成多項式による
めたん
計算は、チェックサムが足し算、CRCが割り算の余り。
めたん
単純なチェックサムは入れ替わりを見逃す。CRCは、まとまって起きる誤りの検出に強いの。
めたん

第5章 ハミング符号

ハミング符号（4ビットのデータ＋3ビット＝7ビット）
  1. 検査①：1・3・5・7ビット目
  2. 検査②：2・3・6・7ビット目
  3. 検査③：4・5・6・7ビット目
  4. どれも1の数が偶数になるよう、1・2・4ビット目を決める
めたん
第5章は、ハミング符号。1ビットの誤りなら、場所まで分かって直せる符号よ。
ずんだもん
ハミング符号って、鼻歌を歌いながら直すのだ？
めたん
ふふ、歌っても直らないわね。
めたん
ここでは、4ビットのデータに3ビットを足して、7ビットにする例で見るわ。
めたん
検査は3つ。検査①は、1、3、5、7ビット目の1の数を見る。
めたん
検査②は、2、3、6、7ビット目。
めたん
検査③は、4、5、6、7ビット目よ。
めたん
どの検査も1の数が偶数になるように、1、2、4ビット目の値を決めておくの。
めたん
大事なのは、どのビットも、入っている検査の組み合わせが違うことよ。
例：正しい符号 0110011 が 0110001 に化けた（説明のための例）
検査①：合う → 0
1・3・5・7ビット目は 0・1・0・1
検査②：合わない → 1
2・3・6・7ビット目は 1・1・0・1
検査③：合わない → 1
4・5・6・7ビット目は 0・0・0・1
めたん
例よ。正しい符号0110011の6ビット目が化けて、0110001が届いたとするわ。
めたん
検査①は、0、1、0、1で偶数。合うから0。
めたん
検査②は、1、1、0、1で奇数。合わないから1。
めたん
検査③は、0、0、0、1で奇数。これも合わないから1。
①×1＋②×2＋③×40＋2＋4＝ 6ビット目が誤り
めたん
この結果を、検査①が1、②が2、③が4の重みで足すの。
めたん
0足す2足す4で、6。6ビット目が誤り、と分かるわ。
めたん
6ビット目を反転すれば、0110011に戻る。これが誤り訂正よ。
ずんだもん
検査の結果が、誤りの住所を教えてくれるのだ！
めたん
そのとおり。ビットの位置を2進数で書くと、仕組みが見えるわ。
めたん
6は2進数で110。4の位と2の位が1だから、6ビット目は検査③と②に入っているの。
めたん
だから6ビット目が化けると、③と②だけが合わなくなる。結果がそのまま位置になるのよ。
ハミング符号で、1ビットと2ビットの誤り
1ビットの誤り2ビットの誤り
検査の結果誤りの位置を指す例：6ビット目別の位置を指すことがある例：6・7ビット目が化けると、1ビット目を指す
直すと元に戻るそのビットを反転すればよい直せない正しいビットを反転してしまう
ずんだもん
じゃあ、ハミング符号なら、何ビット化けても直せるのだ！
めたん
はずれよ。1ビットの誤りなら、検査の結果が誤りの位置を指して、元に戻せる。
めたん
でも、6ビット目と7ビット目の2つが化けると、検査の結果は1ビット目を指すの。
めたん
1ビット目を反転したら、正しいビットを壊してしまう。2ビットの誤りは直せないわ。

めたん
過去問に挑戦。1問目は、令和5年度秋期の午前、問4よ。
めたん
16ビットのデータを4行4列に並べて、行と列にパリティを付ける。何ビットまで直せるかを選ぶ問題よ。
めたん
第3章を思い出して。5秒で考えてみて。

答えはア、1ビットよ。
めたん
1ビットなら、合わない行と合わない列が1本ずつ。交わる所を反転すれば直せるわ。
めたん
2ビットでは、合わない行と列から誤りの位置を一意に決められないの。
誤り検出方式であるCRCに関する記述として，適切なものはどれか。
  • ア　検査用のデータは，検査対象のデータを生成多項式で処理して得られる1ビットの値である。
  • イ　受信側では，付加されてきた検査用のデータで検査対象のデータを割り，余りがなければ送信が正しかったと判断する。
  • ウ　送信側では，生成多項式を用いて検査対象のデータから検査用のデータを作り，これを検査対象のデータに付けて送信する。
  • エ　送信側と受信側では，異なる生成多項式が用いられる。
答えを見るウ　送信側では，生成多項式を用いて検査対象のデータから検査用のデータを作り，これを検査対象のデータに付けて送信する。
出典：令和7年度 秋期 応用情報技術者試験 午前 問4
めたん
2問目は、令和7年度秋期の午前、問4。CRCについて、正しい説明を選ぶ問題よ。
めたん
選択肢が長いから、10秒よ。
めたん
答えはウ。送る側が生成多項式で検査用のデータを作って、データに付けて送るのよ。
めたん
アは、1ビットの値というところが違う。検査用のデータは割り算の余りで、1ビットとは限らないわ。
めたん
イは、さっきのずんだもんの勘違いね。割るのは、検査用のデータではなく生成多項式よ。
めたん
エは逆。送る側と受ける側では、同じ生成多項式を使うわ。
ずんだもん
ぼくの勘違いが、そのまま選択肢になっていたのだ……。

まとめ

ここだけ覚える
  1. 誤り検出は気付くだけ、誤り訂正は直すまで
  2. パリティチェック：1の数を偶数か奇数にそろえる。2ビットの誤りは見逃す
  3. 縦と横のパリティ：交わる所で、1ビットの誤りを直せる
  4. チェックサムは足し算の例。CRCは0を足して生成多項式で割った余りを使う。両側で同じ生成多項式
