ドキュメント型
JSON のような文書を、まるごと1件として保存
ワイドカラム型
行ごとに列の数がちがってもよい
グラフ型
ノードと、そのあいだのつながりを保存

第2章は、NoSQL。

めたん
キーバリュー型は、キーと値の組で保存する。キーを指定して、素早く読み書きできるわ。
めたん
ドキュメント型は、JSONのような文書を、まるごと1件として保存するの。
めたん

第3章 ACID特性とBASE特性

ACID 特性（トランザクションの性質）
原子性
全部実行するか、全部取り消すか
一貫性
決まりに反した状態にしない
独立性
同時に動いても、互いに影響しない
耐久性
確定した結果は、障害が起きても消えない
めたん
第3章は、ACID特性とBASE特性。
めたん
まず、トランザクションが持つ、ACID特性をおさらいするわ。
めたん
原子性は、全部実行するか、全部取り消すか。一部だけ実行した結果を残さないこと。
めたん
一貫性は、決まりに反した状態にしないこと。
めたん
独立性は、同時に動くトランザクションが、互いに影響しないこと。
ずんだもん
互いに影響しない性質なのだ。
めたん
耐久性は、確定した結果が、障害が起きても消えないことよ。
BASE 特性
Basically Available
基本的な可用性を確保する
Soft state
新たな入力がなくても、時間とともに状態が変わり得る
Eventually consistent
結果整合性：更新が落ち着き、通信ができれば、やがて値がそろう
用語：IPA 応用情報技術者試験 シラバス Ver.7.2 9 データベース 5.(2)／定義：AWS「ACID vs BASE Databases」
めたん
これに対して、分散したNoSQLの考え方として、BASE特性があるの。
ずんだもん
ACIDが酸で、BASEが塩基。化学の時間なのだ？
めたん
ふふ、名前は化学みたいね。
めたん
1つ目、Basically Available。基本的な可用性を確保すること。
めたん
2つ目、Soft state。新たな入力がなくても、時間とともに状態が変わり得ることよ。
めたん
3つ目、Eventually consistent。日本語では結果整合性。
めたん
結果整合性では、更新が落ち着き、通信できる状態なら、やがてノード間の値がそろうの。
ずんだもん
いつかは、って、ずっとバラバラでもいいってことなのだ？
めたん
そうではないわ。障害がなければ、いつかはそろう。そろうまでの時間差を認めるの。
ACID 特性と BASE 特性の対決
ACID 特性BASE 特性
重く見ること整合性データに決められた制約を守る可用性更新の反映に時間差があっても、利用を続けることを重く見る
同時処理・更新の扱い独立性同時のトランザクションを互いに切り離す古い値のこともある反映の途中では、ノードによって値がちがう
めたん
ACID特性とBASE特性を並べてみるわ。
めたん
ACIDの一貫性は、データに決められた制約を守ることよ。
めたん
BASE特性は、更新が全体に反映されるまでの時間差を認め、可用性を重く見るわ。
めたん
独立性の説明では、同時のトランザクションを互いに切り離して考えるの。
めたん
BASEでは、反映の途中だと、ノードによって古い値を返すことがあるわ。
ずんだもん
途中では古い値も返るのだ。

第4章 CAP定理

CAP 定理：3つの性質
整合性（C）
完了した更新を、その後の読み取りに反映する
可用性（A）
動いているノードへの要求に、必ず処理結果を返す
分断耐性（P）
ネットワークが分断されても、動き続ける
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 9 データベース 5.(2)
めたん
第4章は、CAP定理。
めたん
Cは整合性。更新が完了した後の読み取りでは、その更新を反映した値が返ること。
めたん
Aは可用性。動いているノードへの要求に、必ず処理結果を返せること。
めたん
Pは分断耐性。ネットワークが途中で切れて分断されても、システムが動き続けること。
ずんだもん
全部そろえれば、最強の分散システムなのだ！
めたん
CAP定理では、ネットワークの分断中に、整合性と可用性の両方を保証することはできないの。
分断が起きたら、どちらを取る？
C と PA と P
分断中の動き一部の要求への応答を止める整合性を保てない要求には、正常な処理結果を返さない受け付けを続ける古い値を返すことがあっても、応答する
あきらめるもの可用性使えない時間ができる整合性最新の値を返す保証をしない
めたん
CとPを取る形は、整合性を保てない要求への応答を止めるの。
めたん
AとPを取る形は、古い値を返すことがあっても、受け付けを続けるわ。

第5章 データウェアハウスとETL

データを分析するしくみ
データウェアハウス
意思決定のために、主題ごとに整理し、過去のデータもためる
データマート
その一部を、特定の用途や部門用に切り出したもの
OLAP
地域別・月別など、いろいろな切り口で集計して分析する
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 9 データベース 5.(1)
めたん
第5章は、データウェアハウスとETL。
めたん
データウェアハウスは、意思決定のために、主題ごとに整理したデータをためる場所。
めたん
今のデータだけでなく、過去のデータもためておくのが特徴よ。
ずんだもん
データウェアハウスで、毎日の注文の受付もするのだ！
めたん
それはちがうわ。毎日の注文のような取引を処理するのは、OLTPと呼ばれる処理よ。
めたん
データウェアハウスは、そこからデータを集めて、分析に使うの。
ずんだもん
分析用にデータを集めるのだ。
めたん
データマートは、データウェアハウスの一部を、特定の用途や部門用に切り出したもの。
めたん
OLAPは、地域別や月別など、いろいろな切り口でデータを集計して分析することよ。
ETL：抽出・変換・格納
  1. Extract（抽出）：元のシステムからデータを取り出す
  2. Transform（変換）：形をそろえ、データクレンジングで誤りや重複を直す
  3. Load（格納）：データウェアハウスに入れる
めたん
データを抽出し、変換してから格納する手順が、ETLよ。
めたん
Eは抽出、Extract。元の業務のシステムから、データを取り出すの。
めたん
Tは変換、Transform。システムごとにちがう形を、そろえるわ。
めたん
このとき、表記のゆれや重複、誤りを直すのがデータクレンジングよ。
ずんだもん
データクレンジングって、ハードディスクを洗剤で洗うのだ？
めたん
ふふ、それは壊れそうね。
めたん
Lは格納、Load。そろえたデータを、データウェアハウスに入れるの。
めたん
先に入れてから変換する、ELTというやり方もあるわ。

まとめ

ここだけ覚える
  1. ビッグデータ：量・種類・速さ。表の形では扱いにくいデータもある
  2. NoSQL：キーバリュー型・ドキュメント型・ワイドカラム型・グラフ型
  3. ACID：トランザクションの4つの性質。BASE：可用性と結果整合性を重く見る
  4. CAP定理：ネットワークの分断中には、整合性と可用性の両方を保証できない
  5. データウェアハウス：分析向けに整理したデータ。データレイク：元の形のデータ
  6. データマイニング：隠れた規則や相関関係を見つける
