第1章 SPF と DKIM

送信元ドメイン認証
何で確かめる改ざんは分かる？
SPF何で確かめる配送用の送信元ドメインのDNS情報で、接続元のIPアドレスが送信を許可されているか検証改ざんは分かる？分からない
DKIM何で確かめる送信側サーバのデジタル署名（公開鍵は DNS に登録）改ざんは分かる？署名対象の改ざんを検出できる
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.56（用語例）、令和4年度 秋期 応用情報技術者試験 午前 問44（SPFの仕組み）。DNS情報・署名対象・各方式の限界は一般的な説明
めたん
送信元ドメイン認証は、送信に使われたドメインの詐称を検証する仕組みよ。
ずんだもん
差出人のアドレスって、自由に書き換えられるのだ？
めたん
そうなの。メールのしくみだけでは、差出人の欄はいくらでも偽れるわ。だから確かめるしくみが要るの。
めたん
SPFは、送ってきたサーバのIPアドレスで確かめる方法。
めたん
SPFでは、配送用の送信元ドメインのDNSに、送信を許可するサーバの情報を登録するの。
めたん
受信側は、そのドメインの情報を使って、接続元のサーバが送信を許可されているか調べるの。
ずんだもん
許可されていないサーバなら、そのドメインを名乗る送信を疑うのだ。
ずんだもん
一覧にあれば、中身も本物なのだ？
めたん
SPFは送信元の検証で、メールの内容の改ざんは検出できないわ。
めたん
DKIMは、送信側のサーバがデジタル署名を付けて、受け取る側が確かめる方法。
めたん
署名を確かめる公開鍵は、これもDNSに載せておくの。
めたん
DKIMでは、署名の対象になった部分が改ざんされると、署名の検証に失敗するの。
ずんだもん
SPFはサーバの住所で、DKIMはハンコで確かめるのだ。

第2章 DMARC

DMARC
1. 確かめる
SPFかDKIMの少なくとも一方が成功し、そのドメインが表示上の差出人と整合すれば合格
2. 扱いを決める
失敗時の方針をDNSで宣言（特別な処置を求めない・隔離・拒否）。実際の扱いは受信側が判断
3. 報告する
報告先の指定と受信側の対応があれば、認証結果の報告を受け取れる
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.56（用語例）。ドメインの整合・方針・報告の仕組みは一般的な説明
めたん
DMARCは、送信元の認証結果と差出人のドメインを照合し、扱いの方針や報告を定める仕組みよ。
ずんだもん
SPFとDKIMがあれば、もう十分なのだ？
めたん
SPFかDKIMの少なくとも一方が成功し、そのドメインが表示上の差出人と整合すれば合格よ。
ずんだもん
合っているか、をわざわざ確かめるのはなぜなのだ？
めたん
認証されたドメインと、表示上の差出人のドメインが違うことがあるからよ。
めたん
そして、失敗したメールをどうしてほしいかを、ドメインの持ち主がDNSで宣言するの。
めたん
宣言する方針は、特別な処置を求めない、隔離、拒否の3つ。実際の扱いは受信側が判断するわ。
めたん
報告先の指定と受信側の対応があれば、認証結果の報告を受け取り、運用状況を確認できるの。

第3章 S/MIME

S/MIME
だれが使う
メールを書く利用者。利用者ごとの証明書を使う
暗号化
受信者の公開鍵を使ってメールを暗号化し、通信途中での盗み読みを防ぐ
署名
秘密鍵で署名。証明書と署名の検証で、署名者の確認と署名対象の改ざん検出を行う
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.56（S/MIME・PGPの用語例）。証明書・暗号化・署名・公開鍵の確認方法は一般的な説明
めたん
第3章はS/MIME。ここまでは、サーバが確かめるしくみだったわね。
めたん
S/MIMEは、メールを書く利用者が使うもの。利用者ごとの証明書を使うの。
めたん
受信者の公開鍵を使ってメールを暗号化し、通信途中での盗み読みを防ぐの。
めたん
署名を検証すると、対応する秘密鍵による署名と、署名対象が変わっていないことを確認できるの。
ずんだもん
DKIMも署名だったのだ。同じものなのだ？
めたん
DKIMはドメインによる署名。S/MIMEは利用者の証明書を使う署名よ。
めたん
同じように、利用者どうしで暗号化と署名をするものに、PGPもあるわ。
ずんだもん
PGPでは、相手の公開鍵が本人のものか、どう確かめるのだ？
めたん
本人に直接確認したり、他の利用者による鍵への署名を使ったりするの。

第4章 Web アプリの弱点と対策

Web アプリの弱点と対策（セキュアプログラミング）
SQL インジェクション
入力に SQL を混ぜてデータベースを操る → プレースホルダ
クロスサイトスクリプティング
入力がスクリプトとして実行される攻撃 → 出力先に合ったエスケープなど
OS コマンドインジェクション
入力がOSの命令として実行される攻撃 → シェルを起動できる言語機能での実装を避ける
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.56〜57（用語例）、令和7年度 春期 応用情報技術者試験 午前 問42（対策）。攻撃の仕組み・出力先に応じたエスケープ・HSTSの動作は一般的な説明
めたん
第4章は、Webアプリの弱点と対策。安全に作ることを、セキュアプログラミングと言うわ。
ずんだもん
Webアプリの弱点って、作った人のミスなのだ？
めたん
設計や実装などに問題があると、入力が意図しない命令として扱われる弱点が生じることがあるわ。
めたん
SQLインジェクションは、入力欄にSQLの一部を混ぜて、データベースを勝手に操る攻撃。
めたん
入力をそのままSQL文につなげると、入力が命令の一部として動いてしまうの。
めたん
対策はプレースホルダ。SQL文の形を先に決めて、入力は値として後から入れるの。
ずんだもん
あやしい文字を消せば、プレースホルダは要らないのだ？
めたん
文字を削るだけでは不十分よ。値は、プレースホルダに対応するパラメータとして渡すの。
めたん
クロスサイトスクリプティング対策では、出力先に合ったエスケープなどで、入力を安全に扱うの。
めたん
HTMLの本文に文字として表示するなら、「<」を「&lt;」にするなどの処理を行うわ。
めたん
OSコマンドインジェクション対策の一つは、シェルを起動できる言語機能での実装を避けることよ。
めたん
HSTSは、サイトがブラウザに、HTTPSで接続する方針を伝える仕組みよ。
めたん
対応するブラウザは方針を覚え、有効期間中は、そのサイトへのHTTP接続をHTTPSに変更するの。

第5章 弱点を探す検査

脆弱性検査
ソースコード静的検査
動かさずに、ソースコードを読んで弱点を探す
プログラムの動的検査
実際に動かして、ふるまいから弱点を探す
ファジング
問題を起こしそうな、いろいろなデータを入れて、動きを見張る
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.56〜57（用語例）、令和4年度 秋期 応用情報技術者試験 午前 問45（ファジングの説明）。検査の比較・入力例・自動化は一般的な説明
めたん
弱点を探す検査は、開発中や運用中に行い、脆弱性の発見につなげるの。
めたん
ソースコード静的検査は、プログラムを動かさずに、コードを読んで弱点を探す方法。
めたん
動的検査は、実際に動かして、ふるまいから弱点を探す方法よ。
ずんだもん
動かさないで読むのと、動かして見るのは、どっちがいいのだ？
めたん
静的検査と動的検査では、見つけられる問題が異なるので、組み合わせて使うの。
めたん
ファジングは、動的検査の一つ。問題を起こしそうな、いろいろなデータを大量に入れて、動きを見張るの。
めたん
長すぎる文字列や、ありえない値を入れて、止まったりおかしな動きをしたら、そこが弱点の候補よ。
ずんだもん
ぼくがキーボードをめちゃくちゃにたたくのも、ファジングなのだ。
めたん
ふふ、キーボードがびっくりしそうね。
めたん
ファジングでは、ツールで入力データの生成や変更、試行を自動化するのが一般的よ。

過去問に挑戦

SPF（Sender Policy Framework）の仕組みはどれか。
  • ア　電子メールを受信するサーバが，電子メールに付与されているデジタル署名を使って，送信元ドメインの詐称がないことを確認する。
  • イ　電子メールを受信するサーバが，電子メールの送信元のドメイン情報と，電子メールを送信したサーバの IP アドレスから，送信元ドメインの詐称がないことを確認する。
  • ウ　電子メールを送信するサーバが，電子メールの宛先のドメインや送信者のメールアドレスを問わず，全ての電子メールをアーカイブする。
  • エ　電子メールを送信するサーバが，電子メールの送信者の上司からの承認が得られるまで，一時的に電子メールの送信を保留する。
答えを見るイ　電子メールを受信するサーバが，電子メールの送信元のドメイン情報と，電子メールを送信したサーバの IP アドレスから，送信元ドメインの詐称がないことを確認する。
出典：令和4年度 秋期 応用情報技術者試験 午前 問44

過去問に挑戦。1問目は、令和4年度秋期の午前、問44よ。
めたん
SPFの仕組みはどれか。5秒で考えてみて。
めたん
答えはイ。送信元のドメインと、送ってきたサーバのIPアドレスで確かめるのが、SPFよ。
ずんだもん
アのデジタル署名は、DKIMのほうなのだ。
めたん
ウはメールの保存、エは送信の承認待ち。どちらも送信元ドメインを検証する説明ではないわ。
ファジングに該当するものはどれか。
  • ア　Web サーバに対し，ログイン，閲覧などのリクエストを大量に送り付け，一定時間内の処理量を計測して，DDoS 攻撃に対する耐性を検査する。
  • イ　ソフトウェアに対し，問題を起こしそうな様々な種類のデータを入力し，そのソフトウェアの動作状態を監視して脆弱性を発見する。
  • ウ　パスワードとしてよく使われる文字列を数多く列挙したリストを使って，不正にログインを試行する。
  • エ　マークアップ言語で書かれた文字列を処理する前に，その言語にとって特別な意味をもつ文字や記号を別の文字列に置換して，脆弱性が悪用されるのを防止する。
答えを見るイ　ソフトウェアに対し，問題を起こしそうな様々な種類のデータを入力し，そのソフトウェアの動作状態を監視して脆弱性を発見する。
出典：令和4年度 秋期 応用情報技術者試験 午前 問45

めたん
ファジングに該当するものはどれか。5秒よ。
めたん
答えはイ。問題を起こしそうなデータを入れて、動きを見張って脆弱性を見つけるの。
めたん
アは大量の通信に耐えられるかの検査。ウは辞書攻撃。エは、第4章のエスケープね。
めたん
そう。ファジングは「見つける」検査。エスケープやプレースホルダは「防ぐ」作り方よ。

まとめ

ここだけ覚える
  1. SPFは接続元のIPアドレスを検証。DKIMは署名対象の改ざんも検出
  2. DMARC：差出人のドメインとの整合を確認し、失敗時の方針や報告先を宣言
  3. S/MIME：利用者の証明書で、暗号化と署名
  4. SQLインジェクション → プレースホルダ、XSS → 出力先に合ったエスケープなど
  5. ファジング：いろいろなデータを入れて、弱点を探す
