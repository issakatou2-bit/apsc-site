組織で守る ― ISMS・インシデント対応・CSIRT

第2章 ISMS

ISMS（情報セキュリティマネジメントシステム）
  1. 計画：適用範囲を決め、リスクを評価し、管理策を選ぶ
  2. 運用：決めた管理策を実施する
  3. パフォーマンス評価：内部監査・マネジメントレビュー
  4. 改善：不適合に是正処置をとり、継続的に改善する
めたん
第2章はISMS。情報セキュリティマネジメントシステムの略よ。
めたん
組織の情報セキュリティ管理の水準を、高めて、維持して、改善していくしくみなの。
めたん
まず計画。どこまでを対象にするか、ISMSの適用範囲を決めて、リスクを評価し、管理策を選ぶ。
めたん
前の回のリスクアセスメントは、ここで使うのよ。
めたん
次に運用。決めた管理策を、実際に行うの。
めたん
そしてパフォーマンス評価。内部監査や、経営陣によるマネジメントレビューで確かめる。
めたん
不適合が見つかったら、原因を取り除く是正処置をとり、再発を防ぐの。
ずんだもん
計画、実行、評価、改善。前にやったPDCAと同じ形なのだ。
めたん
よく気づいたわね。ぐるぐる回して、継続的に改善していくの。
めたん
ISMS認証は、第三者の審査で、JIS Q 27001の要求事項への適合が認められることよ。
ずんだもん
第三者が適合を審査するのだ。
めたん
管理策の手引きになる規格が、JIS Q 27002ね。
情報セキュリティ管理策の4つ（例）
組織的管理策
方針・規程・役割分担を決める
人的管理策
教育・訓練、秘密保持の誓約
物理的管理策
入退室管理、施錠、機器の保護
技術的管理策
アクセス制御、暗号化、マルウェア対策
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 中分類11 ISMS（関連用語。管理策の例は一般的な説明）
めたん
管理策を、組織的、人的、物理的、技術的の4つに分けて見ていくわ。
めたん
組織的管理策。方針や規程、役割分担を決めること。
めたん
人的管理策。教育や訓練、秘密を守る誓約など、人に対する対策よ。
めたん
物理的管理策。入退室の管理、施錠、機器の保護など。
めたん
技術的管理策。アクセス制御、暗号化、マルウェア対策などね。
ずんだもん
ボクのウイルス対策は、技術的管理策の1つだったのだ。
めたん
そう。4つを組み合わせて守るのよ。
めたん
働きによる分類には、発生を防ぐ予防、異常を見つける検知、発生後の影響を抑え回復させる是正があるわ。
ずんだもん
防ぐ、見つける、回復するのだ。
どの管理策？（例は架空）
① サーバ室にカードキーを付けた
→ 物理的管理策
② 新人に、年1回のセキュリティ研修を始めた
→ 人的管理策
③ 社外からの接続に多要素認証を入れた
→ 技術的管理策
④ 情報の持ち出しの規程を作った
→ 組織的管理策
めたん
ここで練習。今から言う対策は、4つのうちどれかしら。例は作り話よ。
めたん
1つ目。サーバ室に、カードキーを付けた。
ずんだもん
部屋の鍵だから、物理的なのだ。
めたん
正解。2つ目。新人に、年1回のセキュリティ研修を始めた。
ずんだもん
人に教えるから、人的なのだ。
めたん
正解。3つ目。社外からの接続に、多要素認証を入れた。
ずんだもん
しくみで守るから、技術的なのだ。
めたん
正解。4つ目。情報の持ち出しについて、規程を作った。
ずんだもん
えっと、決まりだから、組織的なのだ！
めたん
全問正解よ。
攻撃への備えを考える観点の例
  1. 識別：守るものとリスクを把握する
  2. 防御：攻撃を防ぐ対策をとる
  3. 検知：攻撃や異常を見つける
  4. 対応：起きたことに対処する
  5. 復旧：元の状態に戻す
めたん
攻撃への備えの例を、識別、防御、検知、対応、復旧の観点で見てみましょう。
めたん
1つ目は識別。守るものと、そのリスクを把握すること。
めたん
2つ目は防御。攻撃を防ぐ対策をとること。
めたん
3つ目は検知。攻撃や異常を見つけること。
めたん
4つ目は対応。起きたことに対処すること。
ずんだもん
起きたあとの対応も備えなのだ。
めたん
5つ目は復旧。元の状態に戻すことよ。
ずんだもん
防ぐだけじゃなくて、見つけて、対応して、戻すまでがセットなのだ。
めたん
そう。この先の章は、検知、対応、復旧のところの話よ。

第3章 インシデントハンドリング

インシデントハンドリングの流れ
  1. 検知／連絡受付
  2. トリアージ：対応するか、どれから対応するかを決める
  3. インシデントレスポンス（対応）
  4. 報告／情報公開
めたん
第3章は、インシデントハンドリング。インシデントが起きたときの一連の流れよ。
めたん
最初は、検知と連絡受付。自分たちで気づくことも、外から知らせを受けることもあるわ。
めたん
次がトリアージ。対応するかどうか、どれから対応するかを決めるの。
めたん
そしてインシデントレスポンス、対応。被害を広げないようにして、元に戻すの。
めたん
最後に報告と情報公開。関係者に知らせて、必要なら外にも公表するわ。
めたん
偽サイトなどの削除や停止を求める対応を、テイクダウンというわ。
ずんだもん
見つけたら、全部すぐに直せばいいのだ。順番なんていらないのだ。
めたん
人も時間も限られているから、影響や緊急度を考えて優先順位を決める。だからトリアージが要るの。

第4章 デジタルフォレンジックス

デジタルフォレンジックス
何をする
不正アクセスなどの証拠を、電子データから集めて調べる
手順
収集 → 検査 → 分析 → 報告
例
ハードディスクを解析し、削除されたログを復元して痕跡を見つける
出典：令和7年度 秋期 応用情報技術者試験 午前 問44（要約）
めたん
第4章は、デジタルフォレンジックス。
めたん
不正アクセスなどがあったとき、電子データから証拠を集めて調べることよ。
めたん
手順は、収集、検査、分析、報告。
めたん
例えば、ハードディスクを解析して、削除されたログを復元し、不正アクセスの痕跡を見つける。
ずんだもん
ログを集めて、リアルタイムに不正アクセスを見つけるのも、フォレンジックスなのだ？
めたん
この例は、ログのリアルタイム分析による監視・検知の説明ね。

第5章 守る組織 ― CSIRT・PSIRT・SOC

セキュリティを守る組織
CSIRT
組織のセキュリティインシデントに対応するチーム
PSIRT
自社が提供する製品の脆弱性やインシデントに対応する
SOC
ネットワークや機器を監視し、攻撃を検知・分析する
出典：IPA シラバス Ver.7.2 中分類11（関連用語）／令和6年度 春期 午前 問39（製品の脆弱性）／令和7年度 秋期 午前 問40（対応対象）
めたん
第5章。セキュリティを守る組織よ。
めたん
CSIRTは、組織のセキュリティインシデントに対応するチームよ。
めたん
PSIRTは、自社が提供する製品の、脆弱性やインシデントに対応するの。
めたん
SOCは、ネットワークや機器を監視して、攻撃を検知し、分析するの。
ずんだもん
見張るのがSOC、起きたら動くのがCSIRT、製品を守るのがPSIRTなのだ。
めたん
許可された範囲で侵入を試し、弱点を探すペネトレーションテストという方法もあるわ。

過去問に挑戦

ある組織では CSIRT と PSIRT が設置されている。セキュリティインシデントのうち、PSIRT が対応するものはどれか。
  • ア　組織が顧客に販売した製品とその利用において発生したセキュリティインシデント
  • イ　組織が製品の在庫を管理するシステムにおいて発生したセキュリティインシデント
  • ウ　組織が製品の販売を管理するシステムにおいて発生したセキュリティインシデント
  • エ　組織の従業員の個人情報を管理するシステムにおいて発生したセキュリティインシデント
答えを見るア　組織が顧客に販売した製品とその利用において発生したセキュリティインシデント
出典：令和7年度 秋期 応用情報技術者試験 午前 問40
めたん
過去問に挑戦。令和7年度秋期の午前、問40よ。
めたん
CSIRTとPSIRTがある組織で、PSIRTが対応するインシデントはどれか。
ずんだもん
製品という言葉が、たくさん出てくるのだ。
めたん
答えはア。顧客に販売した製品と、その利用で起きたインシデントよ。
めたん
イとウは、製品の在庫や販売を管理する、社内のシステム。エも社内のシステムね。
めたん
この問題では、社内システムのセキュリティインシデントはCSIRTの担当よ。

まとめ

ここだけ覚える
  1. ポリシーの構成例：方針 → 対策基準 → 実施手順
  2. ISMS：計画・運用・評価・改善で、管理の水準を高め続ける
  3. 管理策は組織的・人的・物理的・技術的
  4. インシデントハンドリング：検知／連絡受付 → トリアージ → 対応 → 報告／情報公開
  5. CSIRT は組織、PSIRT は自社製品、SOC は監視
