第1章 ファイアウォール

パケットフィルタリングが見る所
  1. 送信元・宛先の IP アドレス
  2. ポート番号（通信先のサービスを判断する手掛かり）
  3. プロトコル（TCP・UDP など）
  4. 該当するルールが許可なら通し、拒否なら捨てる
めたん
第1章はファイアウォール。異なるネットワーク間などで、ルールに従って通信を制御する仕組みよ。
めたん
基本の方式が、パケットフィルタリング。パケットの見出しを見て、通すかどうか決めるの。
めたん
見るのは、まず送信元と宛先のIPアドレス。ネットワークの基本の回でやった、機器の住所ね。
めたん
次にポート番号。宛先ポート番号は、通信先のサービスを判断する手掛かりになるわ。
めたん
それから、TCPかUDPかといったプロトコル。
めたん
これをルールと比べて、該当するルールが許可なら通し、拒否なら捨てるの。
ファイアウォールの方式
パケットフィルタリング
パケットの見出し（アドレス・ポート番号など）で通すか決める
ステートフルパケットフィルタリング
行きの通信を覚えておき、その応答を通す
アプリケーションゲートウェイ方式
代わりに通信を受け、中身まで見て中継する
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 11 セキュリティ（用語例）
めたん
方式を並べてみましょう。1つ目が、今のパケットフィルタリング。
めたん
2つ目が、ステートフルパケットフィルタリング。行きの通信を覚えておいて、その応答を通すの。
めたん
3つ目が、アプリケーションゲートウェイ方式。代わりに通信を受けて、中身まで見て中継するわ。
ずんだもん
ファイアウォールがあれば、どんな攻撃も止められるのだ！
めたん
そうとは限らないの。通してよい通信に攻撃が混ざっていたら、パケットの見出しだけでは見分けにくいわ。
めたん
だから、ほかの守りと組み合わせるの。それが第3章と第4章よ。

第2章 DMZ（非武装地帯）

構成例：DMZで公開サーバと内部LANを分離する
インターネット（外）
だれでもつながる場所
DMZ
Web サーバなど、外に公開するサーバを置く
内部LAN（社内）
社員の PC や、社内だけで使うサーバ
めたん
第2章はDMZ、非武装地帯。公開サーバを内部ネットワークから分離する区画よ。
めたん
この構成例では、外部がインターネット。
めたん
真ん中がDMZ。Webサーバのような、外に公開するサーバをここに置くの。
めたん
いちばん内側が内部LAN。社員のPCや、社内だけで使うサーバがある所よ。
ずんだもん
ずんだ堂のWebサーバも、内部LANに置けばいちばん安全なのだ。
めたん
置くだけでは安全とはいえないわ。外から公開サーバへの通信を、社内のネットワークまで通すことになるの。
めたん
公開サーバが乗っ取られると、そこから社員のPCなどへ攻撃が広がるおそれがあるの。
この構成例の通信ルール
インターネット → DMZ
公開するサービスの通信だけ通す
インターネット → 内部LAN
直接は通さない
DMZ → 内部LAN
必要な通信だけに絞る
めたん
だからルールはこう。インターネットからDMZへは、公開するサービスの通信だけ通す。
めたん
インターネットから内部LANへは、直接は通さない。
めたん
DMZから内部LANへも、必要な通信だけに絞る。乗っ取られても、社内まで広がりにくくなるわ。
ずんだもん
非武装地帯って、ボクのずんだ餅も取り上げられる場所なのだ？
めたん
取り上げないから、安心して。

第3章 IDSとIPS

ネットワーク型のIDSとIPS（構成例）
IDS（侵入検知システム）IPS（侵入防止システム）
怪しい通信を見つけたら知らせる管理者に通知する（止めない）止める攻撃と判定した通信を自動で遮断する
配置例流れの横通信の写しを受け取って見張る通り道の中監視する通信が通る所に置く
めたん
第3章は見張り役のIDSとIPS。ファイアウォールを通った通信も見て、攻撃らしいものを探すの。
めたん
IDSは侵入検知システム。怪しい通信を見つけたら、管理者に知らせるわ。止めはしないの。
めたん
IPSは侵入防止システム。攻撃と判定した通信を、自動で遮断するの。
めたん
ネットワーク型の構成例を見ましょう。IDSは、通信の写しを受け取って監視するの。
めたん
この例のIPSは、監視する通信の通り道に置くの。そこで通信を遮断できるのね。
ずんだもん
じゃあ、IDSを置けば、攻撃は止まるのだ。
めたん
IDSは知らせるだけ。止めるのは管理者か、IPSのほうよ。名前の検知と防止で覚えてね。
判定の間違い
フォールスポジティブ
正常な通信を、攻撃と判定する（誤検知）
フォールスネガティブ
攻撃を、正常と判定する（見逃し）
IPS で誤検知が起きると
正しい通信まで止めてしまう
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 11 セキュリティ（用語例）
めたん
判定には間違いもあるわ。正常な通信を攻撃と判定するのが、フォールスポジティブ。誤検知ね。
めたん
攻撃を正常と判定して見逃すのが、フォールスネガティブ。
めたん
IPSで誤検知が起きると、正しい通信まで止まってしまうの。
ずんだもん
見逃しは困るし、止めすぎも困るのだ。

第4章 WAF

パケットフィルタリングとWAF
パケットフィルタリングWAF
主に見る所見出しIP アドレス・ポート番号中身Web サーバへの要求（HTTP）の中身
向いている守り通信を絞る決めた相手・サービス以外を通さないWeb アプリを守るSQL インジェクションなどを見つけて止める
めたん
第4章はWAF。Webアプリケーションファイアウォールの略で、Webアプリを守るためのものよ。
めたん
パケットフィルタリングで見るのは、IPアドレスやポート番号などよ。
めたん
WAFは、Webサーバへの要求、HTTPの中身まで見るの。
めたん
パケットフィルタリングは、ルールに従って相手やサービスを絞る守りに向いているの。
めたん
WAFは、SQLインジェクションのような、Webアプリを狙う攻撃を見つけて止める守りに向いているわ。
ずんだもん
WAFがあれば、Webアプリの脆弱性は直さなくていいのだ。
めたん
直さないとだめ。WAFは攻撃を和らげる守り。脆弱性そのものを直すのが基本よ。
WAF による防御が有効な攻撃は？
○ API の脆弱性を狙った攻撃
REST API サービスに対する攻撃（Web への要求）
× DNS キャッシュポイズニング
DNS サーバに対する攻撃
× 第三者不正中継の悪用
SMTP サーバ（メール）の脆弱性を悪用
出典：令和6年度 春期 応用情報技術者試験 午前 問41（要約：解答群から3つ）
めたん
令和6年度春期の午前問41では、WAFが有効な攻撃を選ぶの。
めたん
正解は、REST APIサービスに対する、APIの脆弱性を狙った攻撃。Webへの要求の中身の話ね。
めたん
DNSキャッシュポイズニングは、DNSサーバを狙う攻撃。Webアプリへの要求ではないわ。
めたん
SMTPサーバの第三者不正中継の悪用も、メールの話。WAFが守る所ではないの。
ずんだもん
Webへの要求の中身かどうかで、見分けるのだ。

第5章 VPNとIPsec

VPN と、使うプロトコル
VPN
共有ネットワーク上に、仮想的な専用ネットワークを作る
IPsec
ネットワーク層でIPパケットを保護する。暗号化や改ざん検知
L2TP
データリンク層（レイヤ2）でトンネルを作る。暗号化は IPsec と組み合わせる
TLS を使う VPN
SSL-VPN とも呼ばれる
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 11 セキュリティ（用語例：VPN，IPsec，SSL/TLS）
めたん
第5章はVPN。お店の人が、家から社内のネットワークにつなぐ場面を考えましょう。
ずんだもん
VPNって、お店と家の間に、専用の線を新しく引くのだ？
めたん
この例では、インターネット上に仮想的な専用ネットワークを作るの。物理的な専用線は引かないわ。
めたん
接続相手を認証して通信を暗号化し、外部のネットワークを通る通信を保護するの。
めたん
IPsecは、ネットワーク層でIPパケットを保護する仕組み。暗号化や改ざん検知に使うの。
めたん
保護する対象にした通信は、アプリに個別の暗号化機能がなくても、ネットワーク層で守れるわ。
めたん
L2TPもVPNで使うプロトコル。名前のL2はレイヤ2、データリンク層のことよ。
めたん
L2TPは、それだけでは暗号化しないの。暗号化はIPsecと組み合わせて行うわ。
めたん
TLSを使うVPNもあるわ。SSL-VPNとも呼ばれるの。TLSは次の章よ。

第6章 SSL/TLS

HTTPSの始まり（TLSの構成例）
  1. サーバが、サーバ証明書を送る
  2. ブラウザが、信頼のつながり・有効期限・接続先の名前との一致などを確かめる
  3. 公開鍵暗号の技術で、通信を暗号化する共通鍵を共有する
  4. そのあとの通信は、共通鍵で暗号化する
めたん
第6章はSSL/TLS。TLSは、SSLを引き継いだプロトコルよ。
めたん
Webの通信をTLSで守ったものが、HTTPS。お店の注文画面も、これで守るわ。
めたん
OSI基本参照モデルでは、トランスポート層の上で動くの。
めたん
始めに、サーバがサーバ証明書を送る。
めたん
ブラウザは、信頼のつながりや有効期限、接続先の名前との一致などを確かめるの。
めたん
また、公開鍵暗号の技術を使って、通信を暗号化する共通鍵を共有するの。
めたん
そのあとは、共通鍵で暗号化して通信するの。暗号の回のハイブリッド暗号と同じ考え方よ。
ずんだもん
鍵のマークが出ていれば、そのお店は信用できるお店なのだ。
めたん
そこは注意。分かるのは、通信が暗号化されていて、証明書がそのドメイン名のものだということ。
めたん
偽のサイトでも、自分のドメイン名の証明書は取れるの。お店が正直かどうかまでは分からないわ。

第7章 無線LANとWPA3

無線LANの暗号化
WPA2
無線LANの通信を暗号化する、WPA3 より前からある方式
WPA3
WPA2の後継。無線LANの安全性を高める
Enhanced Open
パスワードの無い無線LANでも、通信を暗号化する
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 11 セキュリティ（用語例）
めたん
最後の第7章は無線LAN。電波は、近くにいればだれでも受け取れてしまうわ。
めたん
だから無線LANの通信は暗号化するの。その決まりが、WPA2やWPA3よ。
めたん
WPA2は、WPA3より前からある方式。
めたん
WPA3はWPA2の後継で、無線LANの安全性を高める方式よ。
めたん
Enhanced Openは、パスワードのない無線LANでも、通信を暗号化する仕組みよ。
めたん
パスワードを使う場合は、推測されにくいものにしてね。

まとめ

ここだけ覚える
  1. パケットフィルタリング：IPアドレスやポート番号などで通信を絞る
  2. DMZ：公開サーバを置く、外と中の間の区画
  3. IDS は知らせる、IPS は止める

  6. TLS：証明書で相手を確かめ、共通鍵で暗号化する
  7. 無線LANは WPA3 などで暗号化する
