持ち出し
USB メモリー・メール・クラウド・スマホのカメラ・紙・口頭

決まりを破った持ち出しや、うっかりの紛失

めたん

めたん

めたん

めたん

VPN 機器などの弱点
脆弱性や設定ミスをついて、社内に入る
アカウントの悪用
総当たりや盗んだ認証情報で、VPNやリモートデスクトップから入る

マルウェアに感染させ、認証の情報を盗む

めたん

第3章 9位 DDoS 攻撃

DDoS 攻撃の手口（IPA 解説書を基に作成）
ボットネット
乗っ取った IoT 機器などから、一斉に大量のアクセス
フラッド攻撃
通信のパケットを大量に送りつける
リフレクション攻撃
送信元を標的に偽って問い合わせ、返事を標的に集める（DNS・NTP）
代行サービス
お金を払えば、技術がなくても頼めてしまう
出典：IPA「情報セキュリティ10大脅威 2026」解説書［組織編］p.36〜37、IPA 応用情報技術者試験 シラバス Ver.7.2 p.49〜50（用語例）
めたん
第3章は9位、DDoS攻撃。分散型サービス妨害攻撃よ。
めたん
大量のアクセスで、Webサイトなどを重くしたり、止めたりするの。
めたん
まず、ボットネット。乗っ取ったIoT機器などに命令して、一斉にアクセスさせるの。
めたん
フラッド攻撃は、通信のパケットを大量に送りつけるもの。
めたん
リフレクション攻撃は、送信元を標的のアドレスに偽って、たくさんのサーバに問い合わせるの。
めたん
応答を標的へ集中させるの。DNSやNTPのサーバが使われるわ。
めたん
それに、お金を払えば頼める代行サービスもあって、技術がなくても攻撃できてしまうの。
めたん
目的には、主義主張の誇示や、攻撃の停止と引き換えの金銭要求などがあるわ。
めたん
試験の用語では、DoS攻撃、DDoS攻撃、リフレクション攻撃、それにボットネットとC&Cサーバよ。
DDoS 攻撃への対策（IPA 解説書を基に作成）
影響を緩和する
CDN、DDoS 対策サービス、WAF・IDS/IPS、冗長化
止まったときに備える
停止時の手順、代わりのサーバ、SNS などでのお知らせ
踏み台にならない
公開サーバの設定を見直す。IoT機器の脆弱性対策を行い、サポート切れを使わない
出典：IPA「情報セキュリティ10大脅威 2026」解説書［組織編］を基に作成
めたん
CDNやDDoS対策サービス、WAFやIPSなどを、攻撃の種類に応じて使うの。
めたん
それでも止まったときのために、手順や代わりのサーバ、SNSなどでのお知らせを準備しておくわ。
めたん
踏み台にならないために、サーバの設定を見直し、IoT機器の脆弱性対策を行うの。
ずんだもん
守るだけじゃなく、攻撃に使われないのも対策なのだ。

第4章 10位 ビジネスメール詐欺

ビジネスメール詐欺のなりすまし（IPA 解説書を基に作成）
取引先になりすます
請求書の口座を、攻撃者の口座に差し替える
経営者になりすます
業務の指示のふりで振り込ませる。「至急」「秘密」と急がせることも
弁護士など第三者
AI で作った偽の声（ディープフェイク）が使われることも
出典：IPA「情報セキュリティ10大脅威 2026」解説書［組織編］を基に作成
めたん
第4章は10位、ビジネスメール詐欺。英語の頭文字でBECとも言うわ。
めたん
取引先や経営者になりすました偽のメールで、偽の口座にお金を振り込ませるの。
めたん
取引先になりすますときは、請求書の振込先を、攻撃者の口座に差し替えるのよ。
めたん
前もってメールのやり取りを盗み見て、本物そっくりの文面とタイミングで送ってくることもあるわ。
めたん
経営者になりすますときは、業務の指示のふりで振り込ませる。「至急」「秘密に」と急がせることもあるわ。
めたん
弁護士などを名乗ることもあるし、AIで作った偽の声、ディープフェイクが使われることもあるわ。
ずんだもん
社長の声で電話が来たら、信じてしまうのだ。
めたん
だから、メールや電話の中身だけで判断しないことが大事なの。
ビジネスメール詐欺への対策（IPA 解説書を基に作成）
別の道で確かめる
口座の変更は、前もって決めた別の連絡手段で確認。メールだけで受け付けない
1人で決めない
支払いは複数人で審査・承認する
技術でも備える
送信元ドメイン認証（SPF・DKIM・DMARC）、S/MIME、多要素認証。正規アカウントの悪用などには別の確認も必要
出典：IPA「情報セキュリティ10大脅威 2026」解説書［組織編］を基に作成
めたん
口座の変更は、前もって決めた別の連絡手段で確認するの。
めたん
依頼メールへの返信や、そこに書かれた電話番号では、攻撃者に確認してしまうおそれがあるわ。
めたん
それから、支払いは1人で決めない。複数人で審査して承認する流れにするの。
めたん
送信元ドメイン認証のSPF・DKIM・DMARCも対策よ。
めたん
ただし、正規のアカウントが悪用されたメールなどは、これだけでは見抜けないわ。

過去問に挑戦

オープンリゾルバを悪用した攻撃はどれか。
  • ア　ICMP パケットの送信元を偽装し，多数の宛先に送ることによって，攻撃対象のコンピュータに大量の偽の ICMP パケットの応答を送る。
  • イ　PC 内の hosts ファイルにある，ドメインと IP アドレスとの対応付けを大量に書き換え，偽の Web サイトに誘導し，大量のコンテンツをダウンロードさせる。
  • ウ　送信元 IP アドレスを偽装した DNS 問合せを多数の DNS サーバに送ることによって，攻撃対象のコンピュータに大量の応答を送る。
  • エ　誰でも電子メールの送信ができるメールサーバを踏み台にして，電子メールの送信元アドレスを詐称したなりすましメールを大量に送信する。
答えを見るウ　送信元 IP アドレスを偽装した DNS 問合せを多数の DNS サーバに送ることによって，攻撃対象のコンピュータに大量の応答を送る。
出典：令和4年度 秋期 応用情報技術者試験 午前 問36。オープンリゾルバの意味と選択肢の分類は一般的な説明

DKIM（DomainKeys Identified Mail）に関する記述のうち，適切なものはどれか。
  • ア　送信側のメールサーバで電子メールにデジタル署名を付与し，受信側のメールサーバでそのデジタル署名を検証して送信元ドメインの認証を行う。
  • イ　送信者が電子メールを送信するとき，送信側のメールサーバは，送信者が正規の利用者かどうかの認証を利用者 ID とパスワードによって行う。
  • ウ　送信元ドメイン認証に失敗した際の電子メールの処理方法を記載したポリシーを DNS サーバに登録し，電子メールの認証結果を監視する。
  • エ　電子メールの送信元ドメインでメール送信に使うメールサーバの IP アドレスを DNS サーバに登録しておき，受信側で送信元ドメインの DNS サーバに登録されている IP アドレスと電子メールの送信元メールサーバの IP アドレスとを照合する。
答えを見るア　送信側のメールサーバで電子メールにデジタル署名を付与し，受信側のメールサーバでそのデジタル署名を検証して送信元ドメインの認証を行う。
出典：令和5年度 秋期 応用情報技術者試験 午前 問44。各選択肢の分類は一般的な説明

まとめ

ここだけ覚える
  1. 内部不正：不正のトライアングル（機会・動機・正当化）。最小特権で機会を減らし、監視で検知・抑止
  2. リモートワーク：VPN機器などを更新し、多要素認証で認証を強化
  3. DDoS：ボットネット・リフレクション。CDNなどで影響を緩和し、踏み台にならない
  4. ビジネスメール詐欺：別ルートでの確認と、送信元ドメイン認証などを組み合わせる
  5. 順位は危険度の順ではない（IPA）
出典：IPA「情報セキュリティ10大脅威 2026」解説書［組織編］p.4・30〜41、IPA 応用情報技術者試験 シラバス Ver.7.2 p.49〜56（用語例）。用語の意味と対策の整理は一般的な説明
めたん
内部不正には、最小特権で機会を減らし、監視で不正を見つけ、抑えるの。
めたん
8位の対策は、VPN機器などの更新と、多要素認証による認証の強化よ。
めたん
9位のDDoSは、ボットネットとリフレクション。受け止めて、踏み台にならない。
めたん
ビジネスメール詐欺には、別ルートでの確認と、送信元ドメイン認証などを組み合わせるの。
めたん
そして、順位は危険度の順ではない。自分の組織に関係するか、どれも確かめておくことよ。
ずんだもん
下の順位でも、油断しないのだ！
