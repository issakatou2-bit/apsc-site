第1章 OSI 基本参照モデル

OSI 基本参照モデル（下から上へ）
  1. 第1層 物理層：電気や光の信号、ケーブル
  2. 第2層 データリンク層：同じリンク内で届ける（イーサネットではMACアドレス）
  3. 第3層 ネットワーク層：最後の宛先まで道を選ぶ（IP アドレス）
  4. 第4層 トランスポート層：アプリ間の通信を支える（TCP・UDPではポート番号）
  5. 第5層 セション層：通信の開始・終了、対話の制御や同期
  6. 第6層 プレゼンテーション層：データの表し方（文字コード・圧縮・暗号）
  7. 第7層 アプリケーション層：アプリへのサービス（Web・メール）
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46、ITU-T X.200（ISO/IEC 7498-1）。各層の役割を要約
めたん
第1章は、OSI基本参照モデル。ISOという国際的な団体が決めた、7つの層の考え方よ。
めたん
下から見ていくわ。第1層は物理層。電気や光の信号、ケーブルやコネクタの決まりね。
めたん
第2層はデータリンク層。同じリンク内でデータを届ける役目。イーサネットではMACアドレスを使うわ。
めたん
第3層はネットワーク層。ネットワークをこえて、最後の宛先までの道を選ぶ役目。IPアドレスを使うの。
ずんだもん
ネットワークを越える道選びなのだ。
めたん
第4層はトランスポート層。アプリ間の通信を支える層で、TCPやUDPではポート番号を使うわ。
めたん
第5層はセション層。通信の開始と終了に加え、対話の制御や同期を管理するの。
めたん
第6層はプレゼンテーション層。文字コードや圧縮、暗号など、データの表し方をそろえるわ。
めたん
第7層はアプリケーション層。Webやメールのような、アプリにサービスを出す層よ。
めたん
下の層の方式が変わっても、上の層へのサービスが同じなら、上の層への影響を抑えられるの。

第2章 TCP/IP の4層

TCP/IPの4層とOSIの大まかな対応
アプリケーション層
OSI の第5〜7層。HTTP・SMTP・DNS など
トランスポート層
OSI の第4層。TCP・UDP
インターネット層
OSI の第3層。IP・ICMP
ネットワークインタフェース層
OSI の第1〜2層。イーサネット・無線 LAN
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46、RFC 1122。層と代表的なプロトコルを要約
めたん
第2章は、TCP/IPの4層。インターネットの通信を、この4層で整理するわ。
めたん
TCP/IPのアプリケーション層は、OSIの第5〜7層に相当する機能を担う。HTTPやSMTPなどね。
めたん
トランスポート層は、OSIの第4層に対応するわ。TCPとUDPが代表例ね。
めたん
インターネット層は、OSIの第3層。IPや、pingで使うICMPがここ。
めたん
一番下のネットワークインタフェース層は、OSIの第1層と2層。イーサネットや無線LANよ。

第3章 層ごとの住所と ARP

層ごとの住所
MAC アドレス（第2層）
イーサネットでは48ビット。同じリンク内の通信に使う識別情報
IP アドレス（第3層）
IPv4 は32ビット、IPv6 は128ビット。最後の宛先の住所
ポート番号（第4層）
その機器の中の、どのアプリに届けるか
ARP
同じリンク内の送信先のIPv4アドレスから、MACアドレスを調べる
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46、RFC 791・8200・826・768。アドレス長・ARP・ポート番号を要約
めたん
第3章は、層ごとに使う識別情報。MACアドレス、IPアドレス、ポート番号を比べるわ。
めたん
MACアドレスは、同じリンク内の通信に使う識別情報。イーサネットでは48ビットよ。
ずんだもん
48ビットで識別するのだ。
めたん
2つ目は、IPアドレス。第3層の住所ね。IPv4は32ビット、IPv6は128ビットよ。
めたん
IPv4の住所が足りなくなってきたから、ずっと多くの住所を使えるIPv6が作られたの。
めたん
3つ目は、ポート番号。第4層で、その機器の中の、どのアプリに届けるかを表すわ。
めたん
たとえるなら、IPアドレスはマンションの住所、ポート番号は部屋番号ね。
ずんだもん
ポートは部屋番号みたいなのだ。
めたん
ARPは、同じリンク内の送信先のIPv4アドレスから、MACアドレスを調べる仕組みよ。
めたん
対応が分からないときは、同じリンク内に問い合わせを送り、該当する機器から返事をもらうの。
MAC アドレスと IP アドレスの対決
MAC アドレスIP アドレス
層と役目データリンク層同じリンク内の通信に使う識別情報ネットワーク層ネットワークをこえて、最後の宛先まで届けるための住所
識別対象と割当てインタフェースの番号ネットワークインタフェースを識別する。物理アドレスとも呼ぶつなぐ所で決まるつなぐネットワークに合わせて割り当てる。変わることがある
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46、RFC 791・826・3022。アドレスの役割と中継を要約
ずんだもん
どっちも住所なら、片方だけでいいのだ。
めたん
両方を使うのは、役目が違うからよ。
めたん
MACアドレスは、ネットワークインタフェースを識別する番号。物理アドレスとも呼ぶわ。
めたん
IPアドレスは、接続するネットワークに合わせて割り当てるの。変わることもあるわ。
めたん
ルータを越えると、宛先MACは次の相手に合わせて変わる。宛先IPは通常の中継では変えないわ。
ずんだもん
バトンを渡す相手と、ゴールのちがいなのだ。

第4章 ポート番号

代表的なウェルノウンポート（0〜1023番）
Web
HTTP 80番、HTTPS 443番
メール
SMTPの中継は25番、メール提出は587番。POP3は110番、IMAP4は143番
名前と時刻
DNS 53番、NTP 123番
そのほか
FTPは制御用21番、標準のデータ用20番（別番号の場合もある）。TELNETは23番
出典：IANA「Service Name and Transport Protocol Port Number Registry」、RFC 6409・959。代表的なポート番号と用途を要約
めたん
第4章はポート番号。0〜1023番は、代表的なサービス用に割り当てるウェルノウンポートの範囲よ。
めたん
Webは、HTTPが80番、暗号を使うHTTPSが443番。
めたん
SMTPの中継には25番、利用者から送信サーバへのメール提出には587番を使うのが代表的よ。
めたん
受け取るほうは、POP3が110番、IMAP4が143番ね。
めたん
名前解決のDNSは53番、時刻合わせのNTPは123番。
めたん
FTPは制御用に21番、標準のデータ用に20番。データ用の番号は変わる場合もあるわ。
ずんだもん
ボク、20番固定かと思ったのだ。
めたん
遠隔操作のTELNETは、23番よ。
めたん
ファイアウォールでは、ポート番号も通信を通すか判断する条件に使うわ。

第5章 TCP と UDP の対決

TCP と UDP の対決
TCPUDP
届け方確かめながら相手とつながってから送り、届いたかを確かめ、足りなければ送り直す到達確認・再送なしUDP自体は接続の確立、到達確認、再送を行わず、到達や順序を保証しない
向いている使い方TCPを使う代表例SMTP・POP3・FTPUDPを使う例NTP、DNSの問い合わせなど。音声や動画の通信に使う場合もある
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46、令和4年度 春期 午前 問33、RFC 1122・768・1035。TCP・UDPの機能と利用例を要約
めたん
第5章は、TCPとUDPの対決。どちらもトランスポート層だけど、届け方がちがうの。
ずんだもん
UDPは、届いたか確かめないなんて、だめなプロトコルなのだ。
めたん
だめとは限らないわ。用途に合わせて、使い分けるの。
めたん
TCPは、相手とつながってから送り、届いたかを確かめて、足りなければ送り直すわ。
めたん
TCPを使う代表例は、SMTP、POP3、FTPよ。
めたん
UDP自体は、到達確認や再送を行わないの。到達や順序も保証しないわ。
めたん
NTPや、DNSの問い合わせなどで使われるわ。音声や動画の通信に使う場合もあるの。
ずんだもん
電話で話している途中なら、少し音が飛んでも、再送を待たず先へ進む方がよい場合もあるのだ。

第6章 つなぐ機器と層

つなぐ機器と層（シラバスの用語例から）
第1層
リピータ・リピータハブ。信号を再生して中継する
第2層
ブリッジ・L2スイッチ。宛先MACアドレスと転送表で送る先を選ぶ
第3層
ルータ・L3 スイッチ。IP アドレスを見て、道を選ぶ
プロトコル変換
ゲートウェイには異なるプロトコルを変換するものがある。対応する層は機能による
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46（装置の用語例）、Cisco「Unicast Flooding in Switched Campus Networks」、RFC 1122。装置の機能を要約
めたん
第6章は、つなぐ機器と層。どの機器が、どの層の情報を見ているかよ。
めたん
第1層は、リピータやリピータハブ。受信した信号を再生して中継し、宛先アドレスは見ないわ。
めたん
リピータハブは、受信した信号を、受信したポート以外のポートへ中継するの。
めたん
第2層は、ブリッジやL2スイッチ。宛先MACアドレスと転送表を使って、送る先を選ぶの。
めたん
宛先を未学習の場合やブロードキャストでは、同じLAN内の複数のポートへ送ることもあるわ。
めたん
第3層は、ルータやL3スイッチ。IPアドレスを見て、次にどこへ渡すか、道を選ぶわ。
めたん
ゲートウェイには、異なるプロトコルを変換してつなぐものがあるわ。対応する層は機能によって違うの。
TCPをイーサネットで送るときのヘッダー
  1. アプリのデータ
  2. TCP ヘッダーを付ける（宛先ポート番号）
  3. IP ヘッダーを付ける（宛先 IP アドレス）
  4. イーサネットヘッダーを付ける（宛先 MAC アドレス）
出典：IPA 令和5年度 春期 応用情報技術者試験 午前 問33、RFC 1122（カプセル化）
めたん
ここでは、TCPのデータをイーサネットで送る場合を見ていくわ。層ごとのヘッダーを付けるの。
めたん
まず、トランスポート層で、TCPのヘッダー。宛先のポート番号が入るわ。
めたん
次に、ネットワーク層で、IPのヘッダー。宛先のIPアドレスが入る。
めたん
最後に、データリンク層で、イーサネットのヘッダー。宛先のMACアドレスね。
めたん
最後に付けたヘッダーが外側。この3つの宛先情報では、MACアドレスが最初に送られるわ。
ずんだもん

まとめ

ここだけ覚える
  1. OSI は7層。下から 物理・データリンク・ネットワーク・トランスポート・セション・プレゼンテーション・アプリケーション
  2. TCP/IP は4層。インターネット層が OSI の第3層
  3. MACは第2層、IPは第3層、ポート番号は第4層。ARPは同じリンク内の送信先のIPv4アドレスからMACアドレスを調べる
  4. TCPは到達確認や再送を行う。UDP自体は行わず、到達や順序を保証しない
  5. リピータハブは第1層、L2スイッチは第2層、ルータは第3層
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 p.43〜46、RFC 1122・768・826。本文の要点を要約
