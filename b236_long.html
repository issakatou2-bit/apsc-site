第1章 トランザクションと ACID 特性

ACID 特性（四つの性質）
A 原子性
全部やるか、全部やらないか
C 一貫性
データの決まり（合計など）がくずれない
I 独立性
同時に動かしても、順番に実行したのと同じ結果になる
D 耐久性
コミットした結果は、障害でも消えない
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 9 データベース 4.(3)
めたん
第1章は、トランザクション。ひとまとまりで扱う処理のことよ。
めたん
例えば、AさんからBさんへの1万円の振込。説明のための作り話ね。
めたん
Aさんの残高から1万円引くことと、Bさんに1万円足すことが、1つのトランザクションよ。
ずんだもん
引いた所で止まったら、引いた分だけ記録されていればいいのだ！
めたん
それだと、1万円が消えてしまうわ。トランザクションには、4つの性質が求められるの。
めたん
1つ目は原子性。全部やるか、全部やらないか。途中で止まったら、全部取り消すの。
ずんだもん
止まったら全部取り消すのだ。
めたん
2つ目は一貫性。2人の残高の合計のような、データの決まりがくずれないこと。
めたん
3つ目は独立性。同時に動かしても、順番に実行したのと同じ結果になること。
めたん
4つ目は耐久性。コミットした結果は、障害が起きても消えないこと。
めたん
コミットは、トランザクションの更新を確定させることよ。頭文字を並べて、ACID特性。
ずんだもん
可用性は入らないのだ。止まらないことは、また別の話なのだ。

第2章 ロック（同時実行制御）

ロックしないと（説明のための作り話：在庫10個）
  1. T1 が在庫を読む：10
  2. T2 も在庫を読む：10
  3. T1 が1個売って 9 を書く
  4. T2 も1個売って 9 を書く
  5. 2個売れたのに在庫は 9（1個分の更新が消えた）
めたん
第2章は、ロック。同時に動くトランザクションがぶつかる話よ。
めたん
在庫が10個の商品を、2つのトランザクションが同時に1個ずつ売る作り話。T1が在庫を読むと10。
めたん
T2も同じときに読んで、10。
めたん
T1は1個売ったから、10ひく1で9を書く。
めたん
T2も、自分が読んだ10から1をひいて、9を書くの。
ずんだもん
2個売れたのに、在庫は9個。1個分の更新が消えたのだ！
めたん
これを防ぐのが、同時実行制御。代表がロックよ。データに鍵をかけて、ほかのトランザクションを待たせるの。
同じデータに別のトランザクションがかけるロックの組合せ
後から共有ロック後から専有ロック
先に共有ロック同時にかけられる読むだけどうしは一緒でよい待つ共有ロックが解除されるまで待つ
先に専有ロック待つ専有ロックが解除されるまで待つ待つ書くのは1つずつ
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 9 データベース 4. トランザクション処理（用語例）
めたん
基本のロックは、読むための共有ロックと、書くための専有ロックよ。
めたん
共有ロックがかかっていても、ほかの人は共有ロックをかけられる。読むだけなら一緒でいいの。
めたん
同じデータに、別のトランザクションが専有ロックをかけるには、共有ロックの解除を待つわ。
ずんだもん
じゃあ、専有ロック中なら、読むだけはできるのだ？
めたん
できないわ。書いている途中の値を読ませないために、共有ロックも待つの。
めたん
同じデータでは、別のトランザクションの専有ロックとも両立しない。共有どうしだけよ。
ずんだもん
共有どうしだけ両立するのだ。
2相ロッキングプロトコルとロック粒度
  1. ① ロックを取得していく。まだ解除しない（取得する相）
  2. ② 外していく（外すだけの相）。外し始めたら、新しくかけない
  3. 同時に動かしても、1つずつ順に動かしたのと同じ結果になる
  4. ロック粒度：表ごと・行ごとなど、ロックをかける単位の大きさ
  5. 粒度が大きい → 管理は楽、待ちが増える／小さい → 待ちは減る、管理が増える
めたん
ロックのかけ方の決まりに、2相ロッキングプロトコルがあるわ。
めたん
最初の相では、必要なロックをかけていくだけ。
めたん
次の相では、外していくだけ。一度外し始めたら、新しいロックはかけないの。
めたん
この決まりを守ると、同時に動かしても、1つずつ順に動かしたのと同じ結果になるわ。
ずんだもん
順に動かした結果になるのだ。
めたん
ロックをかける単位の大きさが、ロック粒度。表ごとにかけるか、行ごとにかけるか。
ずんだもん
表ごと全部ロックすれば、安心なのだ！
めたん
表全体への専有ロックなら、ほかの処理の待ちが増えるわ。粒度を小さくすると、管理の手間は増えるの。
ずんだもん
ぼくのずんだ餅の箱は、1個ずつ鍵をかけるのだ！
めたん
ふふ、鍵を開けるだけで日が暮れそうね。

第3章 デッドロック

デッドロック（作り話）
  1. T1：A を専有ロック → 次に B の専有ロックが欲しい
  2. T2：B を専有ロック → 次に A の専有ロックが欲しい
  3. おたがいに相手を待ち続けて、どちらも進まない
  4. 防ぐ：ロックをかける順番をそろえる（どれも A → B）
  5. 起きたら：片方をロールバックして、やり直させる
めたん
第3章は、デッドロック。ロックの困った面よ。作り話で見るわ。
めたん
T1はデータAに専有ロックをかけて、次にBの専有ロックが欲しい。
めたん
T2は先にBに専有ロックをかけて、次にAの専有ロックが欲しい。
ずんだもん
少し待てば、どちらかが空くのだ。
めたん
空かないの。T1はBを待ち、T2はAを待つ。おたがいに相手を待ち続けて、どちらも進まないわ。
めたん
これがデッドロック。
めたん
防ぐ方法の1つは、ロックをかける順番をそろえること。どれもAからBの順にすれば、待ちの輪ができないの。
めたん
起きてしまったら、片方をロールバックして取り消し、あとでやり直させるわ。

第4章 障害回復

ログに残すものの例（更新前・更新後の値を記録する方式）
  1. 更新前の値（更新前ログ）
  2. 更新後の値（更新後ログ）
  3. トランザクションの開始・コミットの記録
めたん
第4章は、障害回復。まず、回復に使うログの話よ。
めたん
ログは、障害回復に使う記録。ジャーナルファイルとも呼ぶわ。
ずんだもん
回復のために記録を残すのだ。
めたん
ここでは、更新前の値と更新後の値を記録する方式で説明するわ。
めたん
それから、トランザクションの開始とコミットの記録よ。
ロールバックとロールフォワード
ロールバックロールフォワード
使うもの更新前ログ値を更新前に戻す更新後ログ失われた更新をやり直す
する相手未完了のトランザクションコミットしていない更新を取り消すコミット済みのトランザクションコミットした更新をやり直す
出典：IPA 応用情報技術者試験 シラバス Ver.7.2 9 データベース 4. トランザクション処理（用語例）
めたん
ログを使った回復には、向きが2つあるわ。
めたん
ロールバックは、更新前ログを使って、値を更新前に戻すこと。
ずんだもん
更新前の値へ戻すのだ。
めたん
戻す相手は、コミットしていない、未完了のトランザクションよ。
めたん
ロールフォワードは、更新後ログを使って、失われた更新をやり直すこと。
めたん
進め直す相手は、コミット済みのトランザクション。耐久性を守るためね。
チェックポイント（ここでは更新したデータをディスクへ書き出す方式）
  1. ディスクが無事なら、チェックポイント前にコミットした分の再実行は不要
  2. チェックポイントの後にコミット → ロールフォワード
  3. 障害のときに未完了 → ロールバック
  4. ディスクが壊れたとき → バックアップを戻して（リストア）、ロールフォワード
めたん
次はチェックポイント。ここでは、更新したデータをディスクへ書き出す方式で考えるわ。
めたん
その書き出した時点が、チェックポイントよ。
ずんだもん
障害が起きたら、全部のトランザクションをロールフォワードするのだ！
めたん
ディスクが無事なら、チェックポイント前にコミットした分は書けているので、再実行は不要よ。
めたん
チェックポイントの後にコミットした分は、ディスクに書けていないかもしれない。だからロールフォワード。
めたん
障害のときにまだ終わっていなかった分は、ロールバックで取り消すわ。
めたん
ディスクそのものが壊れたら、バックアップを戻すリストアをして、ログでロールフォワードよ。
めたん
最初の勘違いは、ここね。バックアップの後にコミットした更新は、ログで進め直すの。

第5章 2相コミットメント

2相コミットメント（調停者と参加者）
  1. 第1相：調停者が「コミットできる？」と問い合わせる
  2. 参加者が「できる」「できない」と答える（「できる」と答えたら、決定を待つ）
  3. 第2相：調停者が、全員「できる」ならコミット、1つでも「できない」ならロールバックを決めて送る
  4. 「できる」と答えた後に決定が届かないと、参加者は自分で決められない
めたん
第5章は、2相コミットメント。いくつものデータベースにまたがる、分散トランザクションの話よ。
めたん
まとめ役の調停者と、それぞれのデータベースの参加者がいるわ。
めたん
第1相で、調停者が参加者全員に「コミットできる？」と問い合わせるの。
めたん
参加者は「できる」か「できない」と答える。「できる」と答えたら、勝手にやめずに決定を待つの。
めたん
第2相で、調停者が決めて送る。全員「できる」ならコミット、1人でも「できない」ならロールバック。
ずんだもん
全体でコミットするか、全体で取り消すかをそろえて、原子性を守るのだ。
めたん
その通り。でも、「できる」と答えた後に決定が届かないと、参加者は自分では決められないの。
めたん
ほかの参加者がどうなったか、分からないからよ。
ずんだもん
みんなでせーのと言ったのに、合図が来ないと動けないのだ。
めたん
ふふ、まさにその状態ね。

過去問に挑戦

チェックポイントを取得する DBMS において，図のような時間経過でシステム障害が発生した。前進復帰（ロールフォワード）によって障害回復できるトランザクションだけを全て挙げたものはどれか。（図を文で表記：T1 はチェックポイントの前に開始・コミット。T2 はチェックポイントの前に開始し，障害発生時に未完了。T3 はチェックポイントの後に開始し，障害発生時に未完了。T4 はチェックポイントの前に開始し，チェックポイントの後・障害発生の前にコミット。T5 はチェックポイントの後に開始し，障害発生の前にコミット。）
  • ア　T1
  • イ　T2 と T3
  • ウ　T4 と T5
  • エ　T5
答えを見るウ　T4 と T5
出典：令和4年度 秋期 応用情報技術者試験 午前 問29（図を文で表記）

2 相コミットで分散トランザクションの原子性を保証する場合，ネットワーク障害の発生によって参加者のトランザクションが，コミットすべきか又はロールバックすべきかを判断できなくなることがある。このような状況を発生させるネットワーク障害に関する説明として，適切なものはどれか。
  • ア　調停者のトランザクションが，コミット又はロールバック可否の問合せを参加者に送る直前に障害になった。
  • イ　調停者のトランザクションが，コミット又はロールバックの決定を参加者に送る直前に障害になった。
  • ウ　調停者のトランザクションに，コミット又はロールバック可否の応答を参加者が返す直前に障害になった。
  • エ　調停者のトランザクションに，コミット又はロールバックの完了を参加者が返す直前に障害になった。
答えを見るイ　調停者のトランザクションが，コミット又はロールバックの決定を参加者に送る直前に障害になった。

まとめ

ここだけ覚える
  1. ACID：原子性・一貫性・独立性・耐久性
  2. 同じデータでは、別のトランザクションの共有ロックどうしだけ両立する
  3. 2相ロッキング：かける相 → 外す相
  4. デッドロック：ロックの順番をそろえて防ぐ
  5. ロールバックは更新前ログ、ロールフォワードは更新後ログ
  6. 今回の方式：チェックポイント後にコミット → ロールフォワード、未完了 → ロールバック
  7. 2相コミット：「できる」と答えた後に決定が届かないと、決められない
めたん
まとめよ。ACIDは、原子性、一貫性、独立性、耐久性。
めたん
同じデータでは、別のトランザクションの共有ロックどうしだけ両立する。専有ロックがからむと待つ。
めたん
2相ロッキングは、かける相のあとに外す相。
めたん
デッドロックは、ロックの順番をそろえて防ぐ。
めたん
ロールバックは更新前ログ、ロールフォワードは更新後ログ。
めたん
今回の方式では、チェックポイント後にコミットした分はロールフォワード、未完了はロールバック。
めたん
2相コミットは、「できる」と答えた後に決定が届かないと、決められない。
ずんだもん
バックアップ後にコミットした更新があれば、ログで進め直す必要があるのだ！
めたん
その通り。次の回も、いっしょに学びましょう。
