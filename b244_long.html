符号化は、何のため？
情報源符号化
データ圧縮：表現の無駄を減らす
通信路符号化

文字の符号化
文字と数値を対応させ、ビット列で表す
説明用の自作例／一般に確立した知識に基づく解説
めたん
第1章は符号化の目的。同じ符号という言葉でも、何をしたいかで仕組みが違うの。
めたん
情報源符号化はデータ圧縮。表し方の無駄を減らして、少ないビット数で情報を表すの。
めたん
通信路符号化は、通信中などの誤りを検出したり訂正したりするための符号化よ。
めたん
どちらもデータを小さくすることが目的、というわけではないわ。
めたん

めたん

第2章 ハフマン符号

ハフマン符号の説明用データ
出現確率
A：1/2　B：1/4　C：1/8　D：1/8
固定長符号
4種類なら、各記号を2ビットで区別できる
可変長符号
多く出る記号を短く表して平均を減らす
説明用の自作例／一般に確立した知識に基づく解説
めたん
第2章はハフマン符号。出現頻度の違いを利用する、可逆圧縮の基本を見ていくわ。
めたん
ここからの数値は説明用の自作例。記号はA、B、C、Dの四種類とするわ。
めたん
出現確率は、Aが二分の一、Bが四分の一、CとDが八分の一ずつよ。
ずんだもん
四種類を00、01、10、11と書いてみるのだ。二ビットずつで区別できたのだ！
めたん
それが固定長符号ね。ハフマン符号では、多く出る記号を短くして、平均の長さを減らすの。
ずんだもん
では、Aは0、Bは01にすれば、どちらも短くできるのだ？
ハフマン符号の一例
符号表
A＝0　B＝10　C＝110　D＝111
接頭語条件
ある符号が、別の符号の先頭部分にならない
復号の例
010110111 → 0｜10｜110｜111 → ABCD
説明用の自作例／一般に確立した知識に基づく解説
めたん
その割当てでは、01の先頭の0だけでAなのか迷うわ。区切りなしで読める工夫が要るの。
小さい重みを2つずつ結合
  1. C：1/8 と D：1/8 → CD：1/4
  2. B：1/4 と CD：1/4 → BCD：1/2
  3. A：1/2 と BCD：1/2 → 全体：1
  4. 根から葉へ：枝に 0 と 1 を割り当てる
説明用の自作例／一般に確立した知識に基づく解説
めたん
まず各記号を葉として並べるの。重みを出現確率とし、小さい重みを二つ選んで結合するわ。
ずんだもん
小さい二つを先に結ぶなら、この例ではどの組から始めるのだ？
めたん
この例なら、CとDを結合。八分の一と八分の一を足して、新しい重みは四分の一よ。
めたん
次に、Bの四分の一と、今作った組の四分の一を結合。合計は二分の一になるわ。
めたん
最後は、Aの二分の一と、その組の二分の一をつなげて、全体が一になるわ。
めたん
これで木ができたわ。根から枝をたどり、片方を0、もう片方を1にして符号を読むの。
めたん
符号の一例は、Aが0、Bが10、Cが110、Dが111。頻度が高いAは一ビットね。
ずんだもん
多いAは1ビットなのだ。
めたん
どの符号も、ほかの符号の先頭部分になっていないわ。これを接頭語条件というの。
ずんだもん
0を読めばAで確定なのだ！1から始まったら、まだ途中なので続きを読むのだ。
めたん
そう。010110111は、0、10、110、111に分かれ、A、B、C、Dに戻せるわ。
ずんだもん
同じ重みがあると、枝の選び方で符号のビット列が変わることもあるのだ？
めたん
あるわ。左右の0と1を入れ替えても符号長は同じ。ビット列そのものが唯一とは限らないの。
めたん
復号できるように、受け手と同じ符号表を使う必要があるわ。
ずんだもん
受け手の符号表と違ったら、読み違えてしまいそうなのだ。
平均符号長を計算する
確率 × 符号長を足す
1/2×1 ＋ 1/4×2 ＋ 1/8×3 ＋ 1/8×3
平均符号長
1.75 ビット／記号（固定長なら2）
8記号で確かめる
Aが4個・Bが2個・CとDが1個ずつ：14ビット
説明用の自作例／一般に確立した知識に基づく解説
めたん
平均符号長は、各記号の出現確率に符号長を掛けて、全部足して求めるわ。
めたん
二分の一かける一、四分の一かける二、八分の一かける三を二つ。合計は1.75よ。
ずんだもん
固定長の二ビットより短いのだ。でも、CとDは三ビットに長くなっているのだ。
めたん
平均で比べるのが大事ね。Aが四個、Bが二個、CとDが一個ずつなら、計八記号になるわ。
めたん
符号部分は、四かける一、二かける二、三、三を足して14ビット。固定長なら16ビットよ。
ずんだもん
この例なら、保存するファイル全体も、必ず二ビット小さくなるのだ？
めたん
符号表などの情報も必要だから、全体では別に数えるの。小さいデータでは増えることもあるわ。
めたん
各記号を個別に二進の接頭語符号で表す条件では、ハフマン符号は平均符号長を最小にするの。

第3章 Unicode と UTF-8

文字の番号と保存の仕方
Unicode
文字などに符号位置を割り当てる
UTF-8
サロゲートを除く符号位置を1〜4バイトで表す
例
英字 A：U+0041／UTF-8 では 41（16進）
説明用の自作例／一般に確立した知識に基づく解説
めたん
第3章はUnicode。文字を識別する番号と、その番号を保存する仕方を分けて見ましょう。
めたん
Unicodeは、文字などに符号位置を割り当てる規格よ。英字Aの符号位置はU+0041ね。
めたん
その符号位置を、バイト列としてどう表すか。符号化方式の一つがUTF-8なの。
ずんだもん
UTF-8の8は、どの文字も八ビットで表す、という意味なのだ？
めたん
サロゲートを除く符号位置を一から四バイトで表すの。英字Aは一バイトで、16進数の41よ。
同じ「符号化」でも目的が違う
UTF-8
符号位置をバイト列で表す符号化方式
ハフマン符号
出現頻度を利用して平均符号長を減らす
受け手とそろえる
文字なら符号化方式、圧縮なら復号用の規則
説明用の自作例／一般に確立した知識に基づく解説
めたん
文字に番号を付ける名簿と、番号を送るときの書式。そう分けて考えると関係が見えるわ。
ずんだもん
可変長なら、UTF-8もハフマン符号と同じように、頻度を調べて短くするのだ？
めたん
UTF-8は符号位置からバイト列を決める方式。データごとの出現頻度で長さを決める方式ではないの。
めたん
文字を正しく読むには、受け手と文字の符号化方式をそろえる必要があるわ。

第4章 時間計算量とオーダー記号

時間計算量は、入力が増えたとき
入力サイズ n
例：表に格納されたデータの件数
基本操作を数える
例：目的の値との比較を何回行うか
実時間とは区別
同じ回数でも、機械や実装で秒数は変わる
説明用の自作例／一般に確立した知識に基づく解説
めたん
第4章は時間計算量。今度は表現の長さではなく、入力が増えると処理がどう増えるかを見るわ。
めたん
入力サイズをnで表しましょう。表からデータを探す例なら、表の件数がnね。
めたん
例えば、目的の値と比べる操作の回数を数えるの。一回の比較にかかる手間は一定と仮定するわ。
ずんだもん
比較が百回なら、どんなコンピュータでも同じ秒数で終わるのだ？
めたん
秒数は機械や実装でも変わるわ。回数の増え方なら、そうした違いを切り離して比べやすいの。
O 記法：増え方の上界
O(n)
十分大きな n で、定数倍の n 以下に抑えられる
3n＋20 の例
n≧20 なら 3n＋20≦4n：O(n)
よく比較する形
O(1)・O(log n)・O(n)・O(n log n)・O(n²)
説明用の自作例／一般に確立した知識に基づく解説
めたん
オーダー記号のOは、大きい入力に対する増え方の上界を表す記号よ。
めたん
O(n)なら、十分大きいnで、ある定数倍のn以下に処理回数を抑えられる、という意味ね。
めたん
回数が3n＋20なら、nが20以上では4n以下。だから、この式はO(n)と表せるわ。
めたん
定数倍と小さい項を省く、という覚え方は、増え方を比べるためなのよ。
めたん
ただしOは上界。3n＋20をO(n²)とも書けるので、厳密な等式とは違うの。
めたん
Oは最悪の場合専用の記号でもないの。平均の処理回数についても、増え方の上界を表せるわ。
ずんだもん
最悪の場合専用だと思ってたのだ。
めたん
代表的な形は、定数、対数、線形、nログn、二次。画面ではそれぞれOを付けて表しているわ。
ループは、反復回数を数える
別々に繰り返す
n回の処理を2つ並べる：n＋n＝2n
入れ子に繰り返す
外側n回・毎回内側n回：n×n＝n²
半分ずつ減らす
候補数 n → n/2 → n/4 → …：対数的
説明用の自作例／一般に確立した知識に基づく解説
めたん
一回の処理が一定の手間なら、n回のループを二つ順に実行すると、合計は2n回よ。
ずんだもん
ループが二つあるから、二乗になると思っていたのだ。
めたん
別々なら足し算。外側をn回、毎回その内側もn回繰り返す入れ子なら、nの二乗になるわ。
めたん
内側の回数が毎回変わる場合は、その回数を足すの。ループの見た目だけでは決められないわ。
ずんだもん
候補を毎回半分にする探索は、n個を全部見る場合とどう違うのだ？
めたん
八個の候補なら、四個、二個、一個と減るわ。半分にする段数は、対数的に増えるの。
めたん
二分探索では、その段数に応じて比較するからO(log n)。整列されているなどの前提も要るわ。
入力を2倍にしたときの増え方
線形と二次
主要項が n なら約2倍、n²なら約4倍
対数
底2なら log₂(2n)＝log₂ n＋1
条件を見る
平均か最悪か・1回の処理の重さ・前処理
説明用の自作例／一般に確立した知識に基づく解説
めたん
入力を二倍にしたら、線形は約二倍、二次は約四倍よ。増えるほど差が広がるの。
めたん
主要な項で比べた目安ね。底二の対数なら、入力が二倍になると対数の値は一だけ増えるわ。
ずんだもん
対数なら倍々に増える注文も一段ずつなのだ？ボクの胃袋もその方式にしたいのだ！
めたん
ふふ、胃袋は増設できないわね。
めたん
小さい入力では、定数倍や前処理が効く場合もあるの。Oだけで実際の秒数の順位は決まらないわ。
ずんだもん
増え方だけで秒数を決めると、速い方を取り違えそうなのだ。平均か最悪かも確かめたいのだ。
めたん
平均の場合か、最悪の場合かもそろえて比べること。後の過去問では、平均の比較回数を扱うわ。

第5章 NP完全問題

P・NP・NP完全
P
判定問題を多項式時間で解けるクラス
NP
「はい」の答えに、多項式長の証拠があり、多項式時間で検証できるクラス
NP完全
NPに属し、NPの全問題をその問題へ多項式時間で帰着できる
説明用の自作例／一般に確立した知識に基づく解説
めたん
第5章はNP完全問題。速く解けることと、出された答えを速く確かめられることを分けるの。
めたん
まず、答えがはい、いいえになる判定問題を考えるわ。Pは、多項式時間で解けるクラスよ。
めたん
多項式時間とは、入力の長さの固定した累乗など、多項式で処理時間を抑えられることね。
めたん
NPでは、はいという答えに入力長の多項式で抑えられる長さの証拠があり、多項式時間で検証できるの。
答えを探すことと、確かめること
例：巡回経路の判定
全地点を回り、総距離が上限以下になる経路はあるか
候補を検証
訪問先と距離を調べて、条件を満たすか確かめる
NP の注意
Non-Polynomial（非多項式）の略ではない
説明用の自作例／一般に確立した知識に基づく解説
めたん
例えば、全地点を一度ずつ回る経路で、総距離が指定した上限以下になるものがあるかを考えて。
ずんだもん
候補の経路で地点の重複や漏れを調べ、距離を足して確かめるのだ。
めたん
そうね。でも、条件に合う経路を自分で探し出す作業は、それとは別の問題なの。
ずんだもん
NPは非多項式の略で、速く解けないことが証明済み、という意味なのだ？
めたん
違うわ。NPの名前は非決定性多項式時間に由来するの。非多項式という略ではないわ。
めたん
NPにはPも含まれるわ。NP完全問題が多項式時間で解けるかは未解決なの。
ずんだもん
多項式時間で解けるかが未解決なら、NP完全かどうかは何を条件に見分けるのだ？
めたん
NP完全は、NPに属し、NPのどの問題も多項式時間でその問題に変換できる、という二条件よ。
めたん
もし一つのNP完全問題を多項式時間で解ければ、帰着を使ってNPのほかの問題も解けるの。
めたん
その変換を帰着というの。NP完全は、解く方法が全くないという意味でもないわ。

過去問に挑戦

従業員番号と氏名の対が n 件ある表を、先頭から線形探索する。番号はランダムに出現し、表に存在しない確率を a とする。平均比較回数はどれか。
  • ア　(n＋1)na／2
  • イ　(n＋1)(1−a)／2
  • ウ　(n＋1)(1−a)／2＋n／2
  • エ　(n＋1)(1−a)／2＋na
答えを見るエ　(n＋1)(1−a)／2＋na
出典：令和5年度 春期 応用情報技術者試験 午前 問6（問題文を要約・一部改変、数式を1行表記）
めたん
過去問に挑戦。まず、令和5年度春期の午前問6。線形探索の平均比較回数を選ぶ問題よ。
めたん
表には従業員番号と氏名の対がn件あり、先頭から順に比較して、目的の番号を探すの。
めたん
アは(n＋1)na／2、イは(n＋1)(1−a)／2。
めたん
ウはイにn／2を足した式、エはイにnaを足した式よ。
めたん
番号はランダムに出現し、表に存在しない確率はa。見つかる場合と、見つからない場合を考えて。
ずんだもん
見つかる位置は一回からn回なのだ！最初と最後の真ん中を、平均として計算するのだ。
見つかる場合と、見つからない場合
見つかる：確率 1−a
比較回数の平均＝(1＋2＋…＋n)／n＝(n＋1)／2
見つからない：確率 a
最後まで調べるので、比較回数＝n
全体の平均
(n＋1)(1−a)／2 ＋ na
計算量との関係
厳密な平均回数の式と、O(n) を区別する
出典：令和5年度 春期 応用情報技術者試験 午前 問6・解答例（解説は自作）
めたん
見つかる場合は、各位置を同じ確率として、一からnまでの合計をnで割るわ。
めたん
それで平均は、n足す一を二で割った回数。この場合が起きる確率は、一引くaよ。
ずんだもん
表にないときは、比較できないからゼロ回になるのだ？
めたん
ないと分かるのは最後まで調べてから。見つからない場合もn回比較して、その確率がaなの。
めたん
二つの場合の平均回数に、それぞれの確率を掛けて足すわ。後ろにnaが必要なのね。
めたん
正答はエよ。
めたん
確率aがゼロなら平均は(n＋1)／2。一ならn回。端の条件を代入しても確認できるわ。
ずんだもん
O(n)だけでは、この平均回数の選択肢を選べないのだ！式の細部を確かめるのだ。
異なる n 個のデータが昇順に整列された表を、m 個ずつのブロックに分ける。各ブロックの最後尾を線形探索してブロックを特定し、さらにブロック内を線形探索する。平均比較回数はどれか。m は十分大きく、n は m の倍数。目的のデータは必ず表にある。
  • ア　m＋n／m
  • イ　m／2＋n／(2m)
  • ウ　n／m
